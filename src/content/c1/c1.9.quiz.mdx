<Quiz id="1">

**Q1.** Derive that AUC equals the probability a random positive outscores a random negative, then identify the empirical estimator as the normalized Mann–Whitney $U$.

<details>
<summary>Model answer + rubric</summary>

Positives score $X\sim F_+$, negatives $Y\sim F_-$. The ROC plots $\text{TPR}=1-F_+(t)$ vs $\text{FPR}=1-F_-(t)$; parameterize by $u=\text{FPR}=1-F_-(t)$:

$$\text{AUC}=\int_0^1\text{ROC}(u)\,du=\int_0^1\bigl[1-F_+(F_-^{-1}(1-u))\bigr]\,du$$

Substitute $t=F_-^{-1}(1-u)$, $du=-f_-(t)\,dt$ (limits flip):

$$\text{AUC}=\int_{-\infty}^{\infty}\bigl[1-F_+(t)\bigr]f_-(t)\,dt=\int\Pr(X>t)f_-(t)\,dt=\mathbb{E}_Y[\Pr(X>Y\mid Y)]=\Pr(X>Y)$$

— the **concordance probability**. Empirically, replace the probability with the fraction of concordant pairs:

$$\widehat{\text{AUC}}=\frac{1}{n_+n_-}\sum_{i=1}^{n_+}\sum_{j=1}^{n_-}\Bigl[\mathbb{1}(x_i>y_j)+\tfrac12\mathbb{1}(x_i=y_j)\Bigr]=\frac{U}{n_+n_-}$$

where $U$ is the **Mann–Whitney $U$** statistic (= Wilcoxon rank-sum, $U=R_+-\frac{n_+(n_++1)}{2}$ with $R_+$ the positives' rank sum). So AUC is a **rank statistic**: distribution-free, and invariant to any strictly increasing transform of the scores.

**Rubric:**
- Set up $\text{AUC}=\int\text{ROC}(u)\,du$ and substitute to get $\int[1-F_+(t)]f_-(t)\,dt$
- Recognize it as $\Pr(X>Y)$ (concordance)
- Empirical estimator = fraction of concordant pairs = $U/(n_+n_-)$ (Mann–Whitney/Wilcoxon)
- Note: rank statistic → distribution-free, monotone-invariant

</details>

</Quiz>

**Q2.** Prove the ROC curve is unchanged when you multiply the number of negatives by 10, but precision is not. Use both the column-normalization argument and the Bayes form of precision.

<details>
<summary>Model answer + rubric</summary>

**Column-normalization.** $\text{TPR}=\text{TP}/(\text{TP+FN})$ depends only on the positive column; $\text{FPR}=\text{FP}/(\text{FP+TN})$ only on the negative column. Multiply the negatives by 10: at any fixed threshold $\text{FP}\to10\,\text{FP}$ and $\text{TN}\to10\,\text{TN}$ (the score distribution of negatives is unchanged, just 10× as many), so $\text{FPR}=\frac{10\text{FP}}{10\text{FP}+10\text{TN}}=\frac{\text{FP}}{\text{FP}+\text{TN}}$ — **unchanged**. TPR doesn't reference negatives at all. So every ROC point, hence the whole curve and AUC, is invariant. (ROC depends only on the two *class-conditional* score distributions $F_+,F_-$, which resampling class sizes doesn't change.)

**Precision moves.** $\text{Precision}=\text{TP}/(\text{TP+FP})$ mixes a positive count and a negative count. With 10× negatives, $\text{FP}\to10\,\text{FP}$ while $\text{TP}$ is unchanged, so precision *drops*. Via Bayes, precision is the posterior:

$$P=\frac{\text{TPR}\cdot\pi}{\text{TPR}\cdot\pi+\text{FPR}\cdot(1-\pi)}$$

Holding the scorer (TPR, FPR) fixed and lowering the positive prevalence $\pi$ → $P$ falls. So precision/PR-AUC are prevalence-dependent; ROC-AUC is not.

**Rubric:**
- TPR/FPR each normalized within one class → 10× negatives cancels in FPR
- TPR independent of negatives → ROC curve invariant
- Precision mixes classes; $\text{FP}\to10\text{FP}$ with TP fixed → precision drops
- Bayes form $P=\frac{\text{TPR}\,\pi}{\text{TPR}\,\pi+\text{FPR}(1-\pi)}$ → prevalence-dependent

</details>

</Quiz>

<Quiz id="3">

**Q3.** A scorer has TPR = 0.9, FPR = 0.1. Compute precision at $\pi=0.5$ and at $\pi=0.01$. State what happens to ROC-AUC, PR-AUC, and the no-skill PR baseline. Connect to the c1.1 "95%-accuracy trap."

<details>
<summary>Model answer + rubric</summary>

Using $P=\frac{\text{TPR}\,\pi}{\text{TPR}\,\pi+\text{FPR}(1-\pi)}$:

- **$\pi=0.5$:** $P=\frac{0.9(0.5)}{0.9(0.5)+0.1(0.5)}=\frac{0.45}{0.50}=0.90$.
- **$\pi=0.01$:** $P=\frac{0.9(0.01)}{0.9(0.01)+0.1(0.99)}=\frac{0.009}{0.009+0.099}=\frac{0.009}{0.108}\approx0.083$.

**What changes:** **ROC-AUC is unchanged** (same TPR/FPR — Q2). **PR-AUC drops sharply** (precision collapsed from 0.90 to 0.083). The **no-skill PR baseline** is the prevalence: $0.5\to0.01$.

**The trap (c1.1).** At 1% positives over 100k cases, flagging at this operating point catches 900 true positives but also $0.1\times99000=9900$ false ones — 10,800 flagged, 8.3% real. The small FPR over the 99× larger negative pool floods the alert queue, so a 0.9-ROC-AUC model is operationally useless. That's the precise resolution of the "95%-accuracy / 0.9-AUC but useless" trap: ROC-AUC integrates over all thresholds and never exposes that negatives dominate at the operating point.

**Rubric:**
- Precision 0.90 at $\pi=0.5$, ≈0.083 at $\pi=0.01$ (correct arithmetic)
- ROC-AUC unchanged; PR-AUC drops; no-skill PR baseline = $\pi$ (0.5→0.01)
- Imbalance trap: small FPR × huge negative pool floods flagged set
- Tie to c1.1: why a high-AUC model is useless in production

</details>

</Quiz>

**Q4.** Why is `average_precision_score` not the same as `auc(recall, precision)`? Which should you report, and what does Davis–Goadrich (2006) say about the difference?

<details>
<summary>Model answer + rubric</summary>

**They compute different things.** `average_precision_score` (AP) is a **non-interpolated step sum**:

$$\text{AP}=\sum_n (R_n-R_{n-1})\,P_n$$

— the precision at each threshold weighted by the increase in recall. `auc(recall, precision)` runs the generic **trapezoidal** integrator, which **linearly interpolates** between consecutive (recall, precision) operating points.

**Why interpolation is wrong in PR space (Davis–Goadrich 2006).** Unlike ROC space, linear interpolation between two PR points is *not* achievable — the true precision between two operating points follows a nonlinear curve (precision depends on the TP:FP ratio gained, which isn't linear in recall). Trapezoidal PR area therefore connects points with straight lines that lie *above* the true achievable curve, so it **over-estimates** PR-AUC — badly on skewed data (e.g. ~0.53 trapezoidal vs ~0.41 AP on the same model).

**Report AP** (`average_precision_score`); never `auc(recall, precision)`. (Conversely `auc` *is* correct composed with `roc_curve`, since linear interpolation *is* valid in ROC space.)

**Rubric:**
- AP = non-interpolated step sum $\sum(R_n-R_{n-1})P_n$; `auc(recall,precision)` = trapezoidal (interpolates)
- PR interpolation is nonlinear/non-achievable → trapezoidal over-estimates (Davis–Goadrich)
- Report `average_precision_score`
- `auc` is fine for ROC (linear interpolation valid there)

</details>

</Quiz>

**Q5.** Show that applying $p\mapsto p^3$ to all predicted scores leaves AUC unchanged but wrecks log-loss/Brier. Then: which recalibration methods are monotone, and what does that imply about AUC after calibration?

<details>
<summary>Model answer + rubric</summary>

**AUC is invariant.** $p\mapsto p^3$ is strictly increasing on $[0,1]$, so it preserves the *order* of every score: $x_i>y_j \iff x_i^3>y_j^3$. AUC depends only on this pairwise ordering (Q1, concordance), so $\widehat{\text{AUC}}$ is **exactly unchanged**.

**Calibration is wrecked.** Log-loss and Brier depend on the *values*, not just the order. Cubing pushes every score toward 0 (e.g. $0.5\mapsto0.125$, $0.9\mapsto0.729$), so a model that was calibrated now systematically under-predicts — log-loss and Brier rise sharply. They're *proper scoring rules*: minimized only by the true probabilities, which $p^3$ no longer are.

**Recalibration is monotone.** **Platt scaling** (fit a sigmoid $\sigma(as+b)$) and **isotonic regression** (fit a monotone step function) are both **monotone** maps of the scores. Therefore they **leave AUC unchanged** while improving log-loss/Brier/ECE. This is the clean orthogonality result: **ranking (AUC) and calibration are independent** — you can fix calibration without touching discrimination, and a perfect AUC tells you nothing about calibration.

**Rubric:**
- $p\mapsto p^3$ strictly increasing → preserves order → AUC unchanged
- Log-loss/Brier depend on values → degrade (proper scoring rules, minimized at true $p$)
- Platt/isotonic are monotone → improve calibration, leave AUC unchanged
- Conclude: ranking ⊥ calibration

</details>

</Quiz>

**Q6.** Construct a score distribution with AUC ≈ 0.5 that is nonetheless highly predictive. How would you detect and exploit it? Separately, what does AUC = 0.3 tell you to do?

<details>
<summary>Model answer + rubric</summary>

**Construction (non-monotone signal).** Let the positive class concentrate at *both* extremes of the score and negatives in the middle — e.g. positives' scores $\sim$ a mixture of $\mathcal{N}(0.1,\,\text{small})$ and $\mathcal{N}(0.9,\,\text{small})$, negatives $\sim\mathcal{N}(0.5,\,\text{small})$. For a random positive/negative pair, the positive is above the negative about half the time (the high-extreme positives) and below about half (the low-extreme positives) → $P(X>Y)\approx0.5$ → **AUC ≈ 0.5**. Yet the score is *strongly* predictive: "extreme (high *or* low) ⇒ positive, middle ⇒ negative" separates the classes almost perfectly.

**Detect/exploit.** AUC assumes a *monotone* score-to-label relationship; here it's non-monotone (U-shaped). Detect it via a **non-monotone ROC curve** or a **U-shaped reliability/score-vs-rate plot**. Exploit it by transforming the score to restore monotonicity — e.g. use $|s-0.5|$ (distance from the middle) as the new score, on which AUC will be high.

**AUC = 0.3.** The score is *anti-correlated* with the label (negatives outscore positives). **Flip the sign** (use $-s$, or equivalently report $1-\text{AUC}=0.7$). AUC below 0.5 is a labeling/sign bug, not a useless model.

**Rubric:**
- Construct positives-at-both-extremes / negatives-in-middle → $P(X>Y)\approx0.5$ but separable
- AUC assumes monotone score↔label; this is non-monotone
- Detect via non-monotone ROC / U-shaped plot; exploit via $|s-0.5|$
- AUC=0.3 → anti-correlated → flip sign ($1-\text{AUC}=0.7$)

</details>

</Quiz>

**Q7.** With $c_{\text{FN}}=10\,c_{\text{FP}}$ and a *calibrated* model, derive the cost-optimal decision threshold $t^\star$. Where is it on the ROC curve? How does the answer change if the model is uncalibrated?

<details>
<summary>Model answer + rubric</summary>

**Derivation.** Let $p=P(y{=}1\mid x)$ (calibrated). Expected cost of each action (correct predictions cost 0):
- predict **positive**: pay $c_{\text{FP}}$ iff actually negative → $(1-p)\,c_{\text{FP}}$.
- predict **negative**: pay $c_{\text{FN}}$ iff actually positive → $p\,c_{\text{FN}}$.

Predict positive iff its expected cost is lower: $(1-p)c_{\text{FP}}<p\,c_{\text{FN}} \iff p>\dfrac{c_{\text{FP}}}{c_{\text{FP}}+c_{\text{FN}}}=t^\star$. With $c_{\text{FN}}=10\,c_{\text{FP}}$: $t^\star=\frac{1}{1+10}=\frac{1}{11}\approx0.091$. (Missing a positive is 10× costlier, so you flag aggressively — a low threshold.)

**On the ROC curve.** The optimal operating point is where an **iso-cost line of slope** $\frac{(1-\pi)\,c_{\text{FP}}}{\pi\,c_{\text{FN}}}$ is tangent to the ROC curve (the point maximizing TPR-benefit minus FPR-cost).

**If uncalibrated.** $t^\star=c_{\text{FP}}/(c_{\text{FP}}+c_{\text{FN}})$ is only valid on a *calibrated* posterior. If the scores aren't calibrated, thresholding them at $1/11$ doesn't correspond to the cost-optimal decision — you must either **calibrate first** (Platt/isotonic) and then apply $t^\star$, or **tune the threshold empirically** on a validation set against the actual cost (the threshold then absorbs both the miscalibration and the prevalence).

**Rubric:**
- Compare expected costs of the two actions → predict + iff $p>c_{\text{FP}}/(c_{\text{FP}}+c_{\text{FN}})$
- Plug in: $t^\star=1/11\approx0.091$ (aggressive, since FN 10× costlier)
- ROC: iso-cost tangent, slope $\frac{(1-\pi)c_{\text{FP}}}{\pi c_{\text{FN}}}$
- Uncalibrated → formula invalid; calibrate first or tune threshold empirically

</details>

</Quiz>

**Q8.** Show that Youden's J equals both $\text{Sensitivity}+\text{Specificity}-1$ and $\text{TPR}-\text{FPR}$, and that maximizing it is the ROC point farthest above the diagonal. Under what (often unstated) assumption is J the *right* threshold, and when is it wrong?

<details>
<summary>Model answer + rubric</summary>

**Identity.** $J=\text{Sens}+\text{Spec}-1=\text{TPR}+(1-\text{FPR})-1=\text{TPR}-\text{FPR}$. So Youden's J is literally the **vertical gap between the ROC point and the diagonal** (the diagonal is $\text{TPR}=\text{FPR}$, i.e. $J=0$). Maximizing J picks the threshold whose ROC point is **farthest above the chance diagonal**.

**When it's right.** Maximizing $\text{TPR}-\text{FPR}$ weights a unit of TPR exactly as much as a unit of FPR — i.e. it implicitly assumes **equal misclassification costs** ($c_{\text{FP}}=c_{\text{FN}}$) and is **prevalence-agnostic** (the slope-1 iso-utility line). It's the natural default when you have no cost matrix and the classes are balanced (or you don't care about the base rate).

**When it's wrong.** If costs are asymmetric ($c_{\text{FN}}\neq c_{\text{FP}}$) or the prevalence is skewed, the cost-optimal operating point is where the iso-cost line of slope $\frac{(1-\pi)c_{\text{FP}}}{\pi c_{\text{FN}}}$ (≠ 1) is tangent — *not* the max-vertical-distance point. Using Youden's J there over- or under-flags relative to the true cost minimum (Q7). So J is a special case of the cost-optimal threshold at equal costs.

**Rubric:**
- Algebra: $\text{Sens}+\text{Spec}-1=\text{TPR}-\text{FPR}$
- = vertical distance above the ROC diagonal; argmax = farthest point
- Implicit assumption: equal costs (slope-1 iso-utility), prevalence-agnostic
- Wrong under asymmetric costs / skew → use the cost-optimal tangent instead

</details>

</Quiz>

**Q9.** State the Davis–Goadrich dominance theorem precisely. Then give two curves that *cross* in ROC space and explain why "higher ROC-AUC ⇒ higher PR-AUC" fails.

<details>
<summary>Model answer + rubric</summary>

**Theorem (Davis & Goadrich 2006).** For a fixed dataset (fixed prevalence), curve A **dominates** curve B in ROC space (A's ROC lies on or above B's *everywhere*) **if and only if** A dominates B in PR space. Dominance is a *pointwise* relation.

**What does NOT transfer.** The theorem is about *pointwise dominance*, not *areas*. So a **larger ROC-AUC does not imply a larger PR-AUC** when the curves **cross** (neither dominates).

**Crossing example.** Classifier A is excellent in the high-recall / high-FPR region but poor near the origin; classifier B is the reverse (great at low FPR, mediocre at high recall). Their ROC curves cross, so neither dominates. A might have the larger *total* ROC area, yet B — by being stronger in the low-FPR / high-precision region that PR-AUC weights heavily under imbalance — can have the larger PR-AUC. So ranking models by ROC-AUC can disagree with ranking them by PR-AUC. The right move under imbalance is to compare on **PR-AUC** (and at the operating region you care about).

**Rubric:**
- Dominance iff theorem: A ≥ B everywhere in ROC ⇔ everywhere in PR (pointwise)
- Area relationship and converse do NOT transfer
- Construct crossing curves (one strong at high recall, one at low FPR) → no dominance
- Larger ROC-AUC can have smaller PR-AUC → rankings disagree

</details>

</Quiz>

**Q10.** Derive Fβ as a weighted harmonic mean of precision and recall, and map a stated cost preference ("missing a fraud is 4× worse than a false alarm") to a β. Why does F1 implicitly assume something about prevalence/costs?

<details>
<summary>Model answer + rubric</summary>

**Fβ as a weighted harmonic mean.**

$$F_\beta=(1+\beta^2)\frac{PR}{\beta^2P+R}=\left(\frac{1}{1+\beta^2}\cdot\frac1P+\frac{\beta^2}{1+\beta^2}\cdot\frac1R\right)^{-1}$$

— a harmonic mean of $P$ and $R$ with weight $\frac{1}{1+\beta^2}$ on precision and $\frac{\beta^2}{1+\beta^2}$ on recall. So $\beta^2$ is the ratio of how much you weight recall vs precision; $\beta>1$ favors recall, $\beta<1$ favors precision, $\beta=1$ is the symmetric F1.

**Mapping the preference.** "Missing a fraud (a false negative → hurts recall) is 4× worse than a false alarm (a false positive → hurts precision)" → weight recall 4× precision → $\beta^2=4 \Rightarrow \boxed{\beta=2}$. (F2 is the standard "recall matters more" choice.)

**F1's implicit assumption.** F1 ($\beta=1$) weights precision and recall *equally*, and its optimum is **prevalence-dependent**: maximizing F1 corresponds to a particular cost trade that depends on the base rate, and it ignores true negatives entirely. So choosing F1 silently assumes (a) you value FP and FN symmetrically *in the harmonic-mean sense*, and (b) you don't have an explicit cost matrix — when you do, set β from the costs (or threshold on calibrated $p$ at $t^\star=c_{\text{FP}}/(c_{\text{FP}}+c_{\text{FN}})$) instead of defaulting to F1.

**Rubric:**
- Fβ = weighted harmonic mean; $\beta^2$ = recall-vs-precision weight
- "FN 4× worse" → $\beta^2=4$ → $\beta=2$ (F2)
- F1 weights P/R equally; ignores TN; its optimum is prevalence-dependent
- With a cost matrix, set β from costs / use $t^\star$ instead of F1

</details>

</Quiz>

**Q11.** For multiclass AUC in scikit-learn, contrast `multi_class='ovr'` vs `'ovo'`: which is insensitive to class imbalance under `average='macro'`, and why? Separately, when does micro-averaged F1 equal accuracy?

<details>
<summary>Model answer + rubric</summary>

**OvR vs OvO.**
- **`'ovr'`** (one-vs-rest): for each class, AUC of that class vs *all others lumped together*. The composition of the "rest" group changes with class proportions, so even with `average='macro'` (unweighted mean over classes) **OvR is sensitive to class imbalance** — a rare class's "rest" is dominated by the majority.
- **`'ovo'`** (one-vs-one, Hand & Till 2001): average AUC over all *pairs* of classes; each pairwise AUC only involves two classes' conditional score distributions and is itself prevalence-invariant (Q2), so the macro average over pairs is **insensitive to class imbalance**.

So for imbalanced multiclass, prefer `multi_class='ovo'` with `average='macro'`.

**Micro-F1 = accuracy.** In *single-label* multiclass, micro-averaging pools all classes' TP/FP/FN: $\text{micro-}P=\text{micro-}R=\frac{\sum_c \text{TP}_c}{\sum_c \text{TP}_c+\text{FP}_c}$. Every prediction is exactly one TP for some class or one FP (and simultaneously an FN for the true class), so $\sum\text{FP}=\sum\text{FN}=$ (number wrong) and $\sum\text{TP}=$ (number right). Then micro-P = micro-R = micro-F1 = $\frac{\text{\# correct}}{N}$ = **accuracy**. (This breaks in multi-label, where a sample can contribute multiple TP/FP.)

**Rubric:**
- OvR: class-vs-rest; "rest" composition shifts with imbalance → sensitive even under macro
- OvO: pairwise; each pair prevalence-invariant → macro-OvO imbalance-insensitive (Hand–Till)
- Micro-F1 pools TP/FP/FN; in single-label multiclass micro-P=micro-R=accuracy
- (breaks in multi-label)

</details>

</Quiz>

**Q12.** (a) You can only review the top 1% of cases by score — which single metric, and what does sklearn's `max_fpr` return for a random model? (b) With heavy score ties, why do the strict-concordance and trapezoidal AUC disagree, and what's the correct tie handling?

<details>
<summary>Model answer + rubric</summary>

**(a) Partial AUC.** When you only act on the lowest-FPR region (top-scored 1%), the rest of the ROC curve is irrelevant — use **partial AUC** over $[0,\text{max\_fpr}]$ (`roc_auc_score(..., max_fpr=0.01)`). sklearn returns it **McClish-standardized**: it rescales the partial area so that a **random (non-discriminant) model scores 0.5** in the restricted region (and a perfect one scores 1), using `0.5*(1 + (pAUC − min)/(max − min))`. So the number stays comparable to a full AUC.

**(b) Ties.** The concordance derivation (Q1) counts a tied pair ($x_i=y_j$) as **half** ($+\tfrac12$): $\widehat{\text{AUC}}=\frac{1}{n_+n_-}\sum[\mathbb{1}(x_i>y_j)+\tfrac12\mathbb{1}(x_i=y_j)]$. A naive strict-inequality count ($\mathbb{1}(x_i>y_j)$ only) *undercounts* tied pairs, giving a lower value; the trapezoidal ROC integration, by drawing a diagonal segment through the tied region, effectively assigns ties the $\tfrac12$ weight — which is why the trapezoidal AUC and the strict-inequality concordance disagree exactly by the tie contribution. The **correct** handling is the $+\tfrac12$ (mid-rank) convention — equivalent to using average ranks in the Wilcoxon statistic. (Many tied scores, e.g. a tree giving few distinct probabilities, make this non-negligible.)

**Rubric:**
- (a) partial AUC via `max_fpr`; McClish-standardized so random → 0.5 in the region
- (b) ties counted as $+\tfrac12$ in concordance; strict inequality undercounts
- Trapezoidal AUC effectively gives ties the $\tfrac12$ weight (diagonal segment) → matches mid-rank
- Correct handling = $+\tfrac12$ / average ranks; matters with many tied scores

</details>

</Quiz>

**Q1.** You train on a balanced sample ($\bar y=0.5$) but deploy at true prevalence $\tau=0.01$. Derive the additive log-odds correction, and show the corrected model is the *same ranking* as the original — i.e. resampling changed nothing a recalibration couldn't.

<details>
<summary>Model answer + rubric</summary>

**The shift.** By Bayes, the posterior odds factor into prior odds × likelihood ratio. Training at $\bar y$ instead of $\tau$ changes only the *prior* term, multiplying the predicted odds by the ratio of prior-odds:

$$\frac{p_{\text{bal}}}{1-p_{\text{bal}}}=\frac{p_{\text{true}}}{1-p_{\text{true}}}\cdot\frac{\bar y/(1-\bar y)}{\tau/(1-\tau)}$$

Taking logs, the balanced model's log-odds is the true log-odds **plus a constant**:

$$\text{logit}(p_{\text{bal}})=\text{logit}(p_{\text{true}})+\ln\!\Bigl[\frac{\bar y/(1-\bar y)}{\tau/(1-\tau)}\Bigr]$$

So to recover true-prevalence probabilities, **subtract** that constant (King & Zeng's intercept correction): $\text{logit}(p_{\text{corr}})=\text{logit}(p_{\text{bal}})-\ln\bigl[\frac{1-\tau}{\tau}\frac{\bar y}{1-\bar y}\bigr]$. With $\bar y=0.5$, $\tau=0.01$: the shift is $\ln\frac{0.99}{0.01}\approx4.6$ — the balanced model's log-odds are inflated by ~4.6 everywhere.

**Same ranking.** The correction is a *constant added to every score's log-odds*, i.e. a strictly monotone transform of the scores. So it preserves their **order** — the AUC and any ranking are identical to the uncorrected balanced model (c1.9: AUC is monotone-invariant), and the corrected probabilities are just a recalibration. Conclusion: **balancing only shifted the probabilities (and hence the implicit threshold); it didn't change what the model knows.** A recalibration step recovers everything.

**Rubric:**
- Bayes: balancing scales odds by the prior-odds ratio → log-odds shifted by a constant
- King–Zeng correction; compute $\ln(0.99/0.01)\approx4.6$ for $\bar y=0.5,\tau=0.01$
- Constant log-odds shift = monotone → ranking/AUC unchanged
- Conclude: resampling = a probability shift recalibration could undo

</details>

</Quiz>

**Q2.** Derive the cost-optimal threshold $t^\star=C_{\text{FP}}/(C_{\text{FP}}+C_{\text{FN}})$ from expected-cost minimization. Then show that oversampling the minority to a ratio $\rho$ is equivalent to a *specific* threshold on the un-resampled model.

<details>
<summary>Model answer + rubric</summary>

**Threshold derivation.** With calibrated $p=P(y{=}1\mid x)$ and correct predictions costing 0:
- predict **positive** → pay $C_{\text{FP}}$ iff negative → expected $(1-p)C_{\text{FP}}$;
- predict **negative** → pay $C_{\text{FN}}$ iff positive → expected $p\,C_{\text{FN}}$.

Predict positive iff $(1-p)C_{\text{FP}}<p\,C_{\text{FN}} \iff p>\dfrac{C_{\text{FP}}}{C_{\text{FP}}+C_{\text{FN}}}=t^\star$.

**Oversampling ≡ a threshold.** Oversampling the minority by a factor $k$ (until the training odds are $k\times$ the true odds) makes the model learn shifted log-odds: $\text{logit}(p_{\text{re}})=\text{logit}(p_{\text{true}})+\ln k$ (Q1, with $\ln k$ the log of the prior-odds change). The resampled model then uses the *naive* threshold $p_{\text{re}}\ge0.5$, i.e. $\text{logit}(p_{\text{re}})\ge0$, which in terms of the true probability is $\text{logit}(p_{\text{true}})\ge-\ln k$, i.e.

$$p_{\text{true}}\ge\sigma(-\ln k)=\frac{1}{1+k}$$

So oversampling by $k$ and thresholding at 0.5 is **identical** to leaving the model un-resampled and thresholding the true probability at $t=\frac{1}{1+k}$. (Balancing to 50/50 from prevalence $\tau$ corresponds to $k=(1-\tau)/\tau$, giving $t=\tau$ — you've implicitly set the threshold to the prevalence.) The resampling bought you a threshold move you could have made directly — with the bonus downside of degraded calibration (Q7).

**Rubric:**
- Compare expected action costs → $t^\star=C_{\text{FP}}/(C_{\text{FP}}+C_{\text{FN}})$
- Oversampling by $k$ → log-odds $+\ln k$ (prior shift)
- Naive 0.5 threshold on resampled = threshold $1/(1+k)$ on true $p$
- Conclude: resampling ≡ an implicit (uncalibrated) threshold move

</details>

</Quiz>

**Q3.** Construct a dataset where SMOTE *strictly hurts*, and explain the mechanism in terms of SMOTE's interpolation assumption.

<details>
<summary>Model answer + rubric</summary>

**Construction.** Put the minority class in **two separated sub-clusters** with the majority class occupying the region *between* them (an XOR-like / multi-modal layout): minority blobs at $(0,0)$ and $(10,10)$, majority filling the band around $(5,5)$. SMOTE picks a minority point and one of its $k$ minority nearest neighbors and interpolates on the segment between them. When a point in the $(0,0)$ blob has a neighbor in the $(10,10)$ blob (which happens once the blobs are each other's nearest minority neighbors), the synthetic point $x_{\text{new}}=x_i+u(x_i^{(\text{nn})}-x_i)$ lands **in the majority band** around $(5,5)$ — a synthetic "positive" sitting squarely in negative territory.

**Mechanism.** SMOTE assumes the minority class is **locally convex/linear** — that the segment between two minority points stays inside the minority region. When the minority is concave or multi-modal, segments cross into the majority, **injecting synthetic label noise** right on the decision boundary, which drags the boundary into the majority region and *raises* false positives. So SMOTE strictly hurts here versus doing nothing.

(Other valid constructions: high-dimensional data — Blagus & Lusa 2013 show SMOTE leaves class means unchanged and just shrinks variance, so it doesn't help; or categorical features, where interpolating one-hots is meaningless.) The fixes that target this: Borderline-SMOTE/ADASYN (synthesize only near genuine boundaries) or, better, don't SMOTE — threshold + calibrate.

**Rubric:**
- Multi-modal/XOR minority with majority in between
- Interpolation between distant minority blobs → synthetic positive in majority region
- Mechanism: SMOTE's local-convexity assumption violated → injected label noise → boundary dragged
- Note high-dim (Blagus–Lusa) / categorical failure modes as alternatives

</details>

</Quiz>

**Q4.** An engineer SMOTEs the full dataset, then runs 5-fold CV and reports 0.97 PR-AUC; an honest pipeline gives 0.78. Explain the exact leakage mechanism, write the correct ordering, and say why `sklearn.pipeline.Pipeline` can't express it.

<details>
<summary>Model answer + rubric</summary>

**The leak.** SMOTE-before-split synthesizes minority points as **interpolations of real minority points**. After the global SMOTE, the CV splitter divides *all* points (real + synthetic) into folds — so a synthetic point in the *validation* fold is a convex combination of real points that are in the *training* fold (and conversely, a validation real point's near-duplicates/neighbors are in training). The model is therefore scored on points it effectively saw in training → train/test leakage (c1.1's information-availability rule). It's the same structural bug as c1.6's non-OOF stacking: information from the held-out set bled into training. Hence the wildly optimistic 0.97; the honest 0.78 is the truth.

**Correct ordering.** Resample **inside each fold, on the training partition only**, after the split:

```python
from imblearn.pipeline import Pipeline
from imblearn.over_sampling import SMOTE
pipe = Pipeline([("smote", SMOTE()), ("clf", model)])
cross_val_score(pipe, X, y, cv=5, scoring="average_precision")
```

`imblearn`'s `Pipeline` runs the sampler **only on `fit`/`fit_resample`** and **bypasses it on `transform`/`predict`** — so each fold SMOTEs its own training split and the held-out fold is scored at the true prevalence.

**Why `sklearn.pipeline.Pipeline` can't.** sklearn's pipeline only knows `fit`/`transform`/`predict` steps — it has **no notion of a resampling step** that changes the *number of rows* and must act on `fit` but not on `predict`. So you literally cannot place a resampler in it; imbalanced-learn ships its own `Pipeline` precisely to add that `fit_resample` semantics.

**Rubric:**
- Synthetic validation points are interpolations of training points (and vice versa) → leakage
- Same as c1.1 information-availability / c1.6 OOF
- Fix: SMOTE inside `imblearn.pipeline.Pipeline` (sampler on fit only, bypassed on predict)
- sklearn Pipeline has no resample step (can't change row count on fit-only) → imblearn's exists for this

</details>

**Q5.** Prove that reweighting and oversampling share the same expected full-batch gradient, then construct the minibatch-SGD regime where they diverge. When does each need learning-rate retuning?

<details>
<summary>Model answer + rubric</summary>

**Same expected gradient.** Let the minority have per-example loss gradient $g_+$ and there be $n_+$ minority, $n_-$ majority examples. **Oversampling** the minority $k\times$ makes the (summed) training gradient $\sum_{\text{maj}}g + k\sum_{\text{min}}g_+$. **Reweighting** the minority loss by $k$ gives the same summed gradient $\sum_{\text{maj}}g + k\sum_{\text{min}}g_+$. So over a full pass they produce identical (expected) parameter updates — they're equivalent in expectation.

**Divergence under minibatch SGD.** They differ in *variance and dynamics*:
- **Oversampling** changes the *empirical distribution*: the duplicated minority rows appear in many minibatches, so the model takes *many gradient steps on the exact same points* → it can **memorize/overfit** those duplicates (especially with exact ROS). The per-step gradient has normal magnitude but the *data* is repeated.
- **Reweighting** keeps each row once but multiplies its gradient by $k$: a minibatch that happens to contain minority examples produces a **much larger, higher-variance** update (a $k\times$ spike), which can destabilize training.

**LR retuning.** Reweighting inflates effective gradient magnitudes by up to $k\times$, so it typically needs a **smaller / retuned learning rate** (and the `'mean'`-reduction gotcha from c1.2 changes the effective scale). Oversampling keeps gradient magnitudes normal but changes the effective epoch size and overfitting dynamics, so it interacts with **early stopping / regularization** more than with the LR.

**Rubric:**
- Both give summed gradient $\sum_{\text{maj}}g+k\sum_{\text{min}}g_+$ → equal in expectation
- Oversampling: repeated rows → memorization/overfit (data repeated)
- Reweighting: $k\times$ per-example gradient → high-variance/spiky updates
- Reweighting needs LR retuning (magnitude); oversampling interacts with early-stop/regularization

</details>

</Quiz>

**Q6.** Prove ROC-AUC is invariant to prevalence but PR-AUC is not. For a fixed scorer, compute how precision changes going from 50% to 1% positive while ROC-AUC stays fixed.

<details>
<summary>Model answer + rubric</summary>

**ROC invariance.** TPR $=\text{TP}/(\text{TP+FN})$ and FPR $=\text{FP}/(\text{FP+TN})$ are each computed *within a single true class* (column-normalized). Changing prevalence multiplies the count of one class but cancels in its own rate: 10× the negatives sends $\text{FP}\to10\text{FP}$, $\text{TN}\to10\text{TN}$, so $\text{FPR}=\frac{10\text{FP}}{10\text{FP}+10\text{TN}}$ is unchanged; TPR doesn't involve negatives. So every ROC point — and AUC — depends only on the class-conditional score distributions, **not** the prior. ROC-AUC is prevalence-invariant.

**PR moves.** Precision $=\frac{\text{TP}}{\text{TP+FP}}$ mixes both classes; via Bayes $P=\frac{\text{TPR}\,\pi}{\text{TPR}\,\pi+\text{FPR}(1-\pi)}$, which depends on the prior $\pi$. So PR-AUC (and the no-skill PR baseline = $\pi$) moves with prevalence.

**Compute** (scorer fixed at TPR $=0.9$, FPR $=0.1$):
- $\pi=0.5$: $P=\frac{0.9(0.5)}{0.9(0.5)+0.1(0.5)}=0.90$.
- $\pi=0.01$: $P=\frac{0.9(0.01)}{0.9(0.01)+0.1(0.99)}=\frac{0.009}{0.108}\approx0.083$.

So precision falls from **0.90 to ~0.083** (and the PR baseline from 0.5 to 0.01) while **ROC-AUC is identical**. That's why imbalanced evaluation must use PR-AUC (c1.9), not ROC-AUC.

**Rubric:**
- TPR/FPR column-normalized → prevalence cancels → ROC invariant
- Precision via Bayes depends on $\pi$
- Compute 0.90 → 0.083 for fixed TPR/FPR
- Conclude: use PR-AUC for imbalanced evaluation

</details>

</Quiz>

**Q7.** A model is perfectly calibrated at $\tau=0.02$. After balancing to 50/50, what happens to its reliability diagram, and what single step undoes the distortion?

<details>
<summary>Model answer + rubric</summary>

**The distortion.** Balancing from $\tau=0.02$ to $\bar y=0.5$ multiplies the predicted odds by $\frac{\bar y/(1-\bar y)}{\tau/(1-\tau)}=\frac{1}{0.02/0.98}=49$ (Q1). So the balanced model's predicted probabilities are **systematically inflated** for the positive class — a case it truly thinks is $p_{\text{true}}=0.1$ now reports $\sigma(\text{logit}(0.1)+\ln 49)\approx\sigma(-2.197+3.892)=\sigma(1.695)\approx0.845$. On a reliability diagram (predicted prob on x, empirical rate on y), the curve falls **well below the diagonal**: at a predicted 0.845 the empirical positive rate is only ~0.1. The model is now badly over-confident in the positive direction — exactly the van den Goorbergh et al. (2022) finding that resampling preserves ROC-AUC (monotone, c1.9) but wrecks calibration.

**The fix (one step).** **Prior correction:** subtract the constant log-odds shift, $\text{logit}(p_{\text{corr}})=\text{logit}(p_{\text{bal}})-\ln\frac{\bar y/(1-\bar y)}{\tau/(1-\tau)}=\text{logit}(p_{\text{bal}})-\ln 49$. This maps the inflated probabilities back onto the diagonal and recovers the original calibrated model (equivalently, refit the intercept, or run `CalibratedClassifierCV` on a held-out set at the true prevalence). Since it's a monotone transform, AUC is unchanged — only the probabilities are repaired.

**Rubric:**
- Balancing inflates odds by $\frac{1}{\tau/(1-\tau)}=49$ → probabilities over-estimated
- Reliability curve sits below the diagonal (over-confident positive); cite van den Goorbergh 2022
- Fix: subtract the $\ln 49$ log-odds shift (prior correction) / recalibrate
- Monotone → AUC unchanged, calibration restored

</details>

</Quiz>

**Q8.** Compute `class_weight='balanced'` for 30 positives / 970 negatives. Then explain the interaction with a loss that uses `'mean'` reduction over weighted examples.

<details>
<summary>Model answer + rubric</summary>

**Weights.** sklearn's formula is $w_c=\frac{N}{K\,n_c}$ (n_samples / (n_classes × class count)). With $N=1000$, $K=2$:
- $w_{\text{pos}}=\frac{1000}{2\cdot30}=\frac{1000}{60}\approx16.67$.
- $w_{\text{neg}}=\frac{1000}{2\cdot970}=\frac{1000}{1940}\approx0.515$.

(Ratio $\approx 32.3$, i.e. the minority's IR — each positive counts ~32× a negative, equalizing the two classes' total weight: $30\times16.67\approx970\times0.515\approx500$ each.)

**`'mean'`-reduction interaction.** A weighted loss reduced by `'mean'` typically divides the weighted sum by the **sum of weights present in the batch**, not by the batch size $N$ (the c1.2 `pos_weight` gotcha). So the *effective* per-batch normalizer changes batch-to-batch depending on how many minority examples it contains — a minority-heavy batch has a larger weight sum, shrinking each example's contribution. The practical consequence: the **effective learning rate fluctuates** with batch composition, and a batch with *zero* positives still contributes a full majority gradient with no minority counterweight. Mitigations: use stratified/`WeightedRandomSampler` batches so each minibatch contains minority examples, and retune the LR after adding class weights (or use sum-reduction with an explicit normalizer you control).

**Rubric:**
- $w_{\text{pos}}=1000/60\approx16.7$, $w_{\text{neg}}=1000/1940\approx0.515$ (ratio ≈ IR)
- Equalizes total class weight (~500 each)
- `'mean'` divides by sum-of-weights-present → effective LR varies with batch composition (c1.2 gotcha)
- Fix: stratified batches + LR retune; zero-positive batches are a hazard

</details>

**Q9.** Given a labeled neighborhood, classify a minority point as safe / danger / noise (Borderline-SMOTE), and compute ADASYN's synthesis allocation. Construct a configuration where ADASYN over-concentrates synthesis on a mislabeled outlier.

<details>
<summary>Model answer + rubric</summary>

**Borderline-SMOTE labels.** For a minority point, look at its $m$ nearest neighbors (any class) and let $m'$ = number that are *majority*:
- **safe:** $0\le m'<m/2$ (mostly minority neighbors);
- **danger (borderline):** $m/2\le m'<m$ (mostly majority — near the boundary);
- **noise:** $m'=m$ (all majority — an isolated minority point).

Borderline-SMOTE synthesizes only from the **danger** set (concentrate effort on the boundary). E.g. with $m=10$: $m'=2$ → safe, $m'=7$ → danger, $m'=10$ → noise.

**ADASYN allocation.** For each minority point $i$, $r_i=(\text{\# majority among its }k\text{-NN})/k$; normalize $\hat r_i=r_i/\sum_j r_j$; generate $g_i=\hat r_i\cdot G$ synthetic points (G = total to create). So *harder* minority points (more majority neighbors) get *more* synthesis — a continuous version of Borderline's hard threshold.

**The failure (mislabeled outlier).** Consider a single minority point mislabeled deep inside majority territory: all $k$ of its neighbors are majority, so $r_i=1$ (the maximum), and if other minority points are "safe" ($r_j$ small), this outlier's normalized $\hat r_i$ dominates → ADASYN pours a large share of $G$ synthetic positives **around a mislabeled point in the majority region**, manufacturing a cluster of bogus positives that wrecks the boundary. (Borderline-SMOTE would tag it *noise* ($m'=m$) and skip it — which is exactly why the noise category exists.) Lesson: density-adaptive synthesis is sensitive to label noise; clean labels or prefer threshold+calibrate.

**Rubric:**
- safe/danger/noise via $m'$ relative to $m/2$ and $m$; Borderline uses danger only
- ADASYN: $r_i$ = majority fraction in $k$-NN, $g_i=\hat r_i G$ (more for harder points)
- Construct mislabeled outlier with $r_i=1$ dominating $\hat r_i$ → synthesis concentrates on it
- Borderline tags it noise and skips; ADASYN's adaptivity is noise-sensitive

</details>

**Q10.** At 1:10,000 imbalance, argue from estimation variance why an anomaly-detection framing can beat balanced binary classification. Which method for a *contaminated* training set, and how do you set $\nu$ / `contamination`?

<details>
<summary>Model answer + rubric</summary>

**Why reframe.** At 1:10,000 with, say, 100k rows, you have ~10 positives. You cannot estimate a decision boundary or per-class densities from 10 points — the variance of any minority-class parameter estimate is enormous, and any resampling just duplicates/interpolates those 10 points (manufacturing fake confidence, not information). **Anomaly detection** instead models the *majority/normal* distribution (which you have abundant data for) and flags points that don't fit — turning "learn a boundary from 10 positives" into "learn normality from 100k negatives," a far lower-variance problem.

**Clean vs contaminated.**
- **One-Class SVM** (Schölkopf 2001) learns a boundary around a $\nu$-fraction of the training data — it assumes the training set is essentially **clean** (pure normal); it's a *novelty* detector. Use it when your "normal" training data has (almost) no anomalies.
- **Isolation Forest** (Liu 2008) isolates points via random splits (anomalies need fewer splits → shorter path length); it's robust to **contaminated, multimodal** data — use it when the training set itself contains some anomalies (outlier detection).

So for a **contaminated** training set → **Isolation Forest**.

**Setting the knob.** Both expose a fraction parameter tied to the expected anomaly rate: One-Class SVM's $\nu$ is an upper bound on the fraction of outliers (and a lower bound on the support-vector fraction); Isolation Forest's `contamination` is the expected proportion of anomalies (sets the score threshold). Set it to your **prior anomaly rate** ($\approx10^{-4}$ here), or tune it on a labeled validation subset against the cost-weighted metric.

**Rubric:**
- ~10 positives → huge estimation variance; resampling adds no information
- Reframe: model normal (abundant) + flag outliers → lower-variance problem
- One-Class SVM = clean/novelty; Isolation Forest = contaminated/outlier → pick IForest for contaminated
- $\nu$ / `contamination` ≈ prior anomaly rate (or tune on labeled validation)

</details>

</Quiz>

**Q11.** At 1000:1, compare the compute and statistical costs of oversampling-to-balance vs undersampling-to-balance. Show undersampling discards mostly *easy* negatives, and design an ensemble that recovers the hard ones without the memory blowup.

<details>
<summary>Model answer + rubric</summary>

**Compute.** Oversampling to balance multiplies the *minority* up to match the majority — at 1000:1 that's ~1000× the minority, roughly **doubling** the dataset to ~2× the majority count (huge if the majority is already large), and training on mostly synthetic/duplicated rows. Undersampling to balance **drops ~99.9% of the majority**, leaving a tiny dataset (2× the minority) that trains in a fraction of the time and memory. So at extreme IR, **undersampling is the only thing that scales**.

**Statistical cost of undersampling.** A *random* undersample keeps a uniform sample of negatives — but the decision-relevant negatives are the **hard ones near the boundary** (easy negatives far from the boundary carry little gradient signal, c1.1's hard-negative point). Random undersampling discards them in proportion, so you throw away most of the *informative* negatives along with the easy ones, raising variance and hurting the boundary.

**Ensemble fix (EasyEnsemble / BalancedRandomForest).** Instead of one undersample, draw **many** independent balanced subsets (each = all minority + a fresh random undersample of the majority), train a classifier on each, and **aggregate** (vote/average). Across the ensemble, *most* of the majority — including the hard negatives — gets seen by *some* member, so collectively you use the full negative set, while each member stays small (memory ≈ one balanced subset at a time). This recovers the hard negatives undersampling would otherwise discard, without the oversampling memory blowup. (Informed undersampling — Tomek links / NearMiss — is the alternative: drop *easy* negatives preferentially.)

**Rubric:**
- Oversample → ~2× majority (compute/memory blowup); undersample → tiny (scales) at extreme IR
- Random undersampling discards informative hard negatives (c1.1)
- EasyEnsemble/BalancedRF: many balanced subsets + aggregate → covers all negatives, small per-member memory
- (or informed undersampling: Tomek/NearMiss drop easy negatives)

</details>

</Quiz>

**Q12.** You're handed a 1000:1 fraud dataset. Specify the full protocol — split, whether/where to resample, metric, and final operating point — and defend *not* using SMOTE.

<details>
<summary>Model answer + rubric</summary>

**Split.** **Stratified** (preserve the 1000:1 ratio in each fold so the rare class appears — c1.1), and if the data is time-ordered and entity-grouped, **temporal forward-chaining + grouped** (no future leakage, no entity straddling — c1.1). At 1000:1, ensure each validation fold has enough positives to estimate recall (or use repeated stratified CV).

**Resample? Where?** Default: **don't resample.** Train a strong probabilistic model (e.g. gradient-boosted trees) with optionally `class_weight`/`scale_pos_weight` for gradient signal. If you do resample (validated to help), put it **strictly inside the CV pipeline** (`imblearn.pipeline.Pipeline`) so only training folds are resampled — never SMOTE-then-split (Q4).

**Metric.** **PR-AUC / average precision** (ROC-AUC hides the precision collapse at 1000:1 — c1.9), plus precision/recall at the chosen operating point; pick the threshold from the **cost matrix**.

**Operating point.** **Calibrate** the model (Platt/isotonic, or prior-correct), then set the threshold $t^\star=C_{\text{FP}}/(C_{\text{FP}}+C_{\text{FN}})$ on the calibrated probability. (At 1000:1 you may also reframe as **anomaly detection** — Q10.)

**Why not SMOTE.** (1) **Elor & Averbuch-Elor 2022:** for strong probabilistic learners with a *tuned threshold*, SMOTE gives **no benefit** — its apparent gains are an artifact of leaving the threshold at 0.5. (2) **Resampling = an implicit threshold shift** (Q1–Q2) that also **breaks calibration** (van den Goorbergh 2022) — so it does nothing a calibrated threshold can't, with worse probabilities. (3) At 1000:1 in any real feature dimension, SMOTE's interpolation assumption is shaky (Blagus–Lusa). So: calibrate + threshold (+ maybe anomaly framing), and reach for SMOTE only if it provably beats that on PR-AUC inside a leakage-safe pipeline.

**Rubric:**
- Stratified (+ temporal/grouped if applicable) split; enough positives per fold
- Default no resample; if any, inside `imblearn.pipeline.Pipeline` (never SMOTE-then-split)
- PR-AUC / AP + cost-based threshold (not ROC-AUC)
- Calibrate + $t^\star=C_{\text{FP}}/(C_{\text{FP}}+C_{\text{FN}})$; consider anomaly framing
- Defend no-SMOTE: Elor 2022 (no benefit with tuned threshold) + resampling=threshold-shift+miscalibration (van den Goorbergh) + Blagus–Lusa

</details>
