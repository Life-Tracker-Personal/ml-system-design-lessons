## TL;DR

Ensembles are **bias-variance engineering**. Start with the base learner. A single decision tree is a *low-bias, high-variance* learner: flexible enough to fit anything, unstable enough to fit noise. There are exactly two ways to fix that, and they pull opposite levers.

**Bagging / random forests** average many high-variance trees to crush **variance**. The whole game there is *decorrelating* the trees, and one identity tells you why.

**Boosting** adds many high-bias weak trees in sequence to crush **bias**. The whole game there is *fitting the negative gradient of the loss in function space*, and one gradient tells you why.

Knowing which lever each family pulls, plus the one identity and the one gradient that make each precise, is enough to reason about any ensemble you meet. These models are not history either: gradient-boosted trees especially still win most tabular problems.

## What you'll be able to do after this lesson

- Compute the impurity decrease of a split (Gini, entropy, variance reduction) and explain why a single tree is low-bias/high-variance.
- Derive the bagging **decorrelation identity** $\rho\sigma^2 + \frac{1-\rho}{B}\sigma^2$ and explain what random forests do to $\rho$.
- Derive the OOB $\sim37\%$ (the $1/e$ result).
- Show AdaBoost is forward-stagewise minimization of **exponential loss** and derive its stagewise coefficient $\beta=\tfrac12\ln\frac{1-\text{err}}{\text{err}}$ (the classifier vote is $\alpha_m=2\beta$).
- Explain gradient boosting as **functional gradient descent** (pseudo-residuals) and derive XGBoost's leaf weight $w^\star=-G/(H+\lambda)$.
- Explain why stacking needs **out-of-fold** predictions, and diagnose feature-importance and calibration traps.

## Why trees & ensembles deserve their own chapter

> **Goal — master the model family that actually wins on tabular data, and the bias-variance reasoning behind it.** **Gradient-boosted decision trees still beat tuned neural nets on most tabular problems** (Grinsztajn et al. 2022) — because trees handle uninformative features gracefully, match the axis-aligned structure of real tabular data, and fit irregular target functions that NN smoothness priors resist; that is the "trees dominate tabular" claim from c1.1, with its citation attached. Ensembles are where bias-variance stops being a slogan and becomes an engineering decision.

Six terms recur throughout, and three of them — bootstrap, bagging, boosting — sound nearly alike. Each is pinned down here so that later it arrives as a label for something already understood rather than a word to decode mid-derivation.

> **Vocabulary primer.**
>
> - **Impurity** — how mixed a node's labels are (Gini, entropy for classification; variance for regression). Splits reduce it.
> - **Base / weak learner** — the simple model an ensemble combines (here, a decision tree; "weak" = slightly better than chance).
> - **Bagging** — bootstrap aggregating: fit base learners on bootstrap resamples and average them.
> - **Boosting** — fit base learners *sequentially*, each correcting its predecessors' errors.
> - **OOB (out-of-bag)** — the ~37% of rows a given bootstrap tree didn't see; free validation data.
> - **Pseudo-residual** — the negative gradient of the loss w.r.t. the current prediction; what gradient boosting fits next.

## Part 1 — Decision trees (CART)

> **Goal — understand the base learner: a greedy, axis-aligned partition that is flexible (low bias) but unstable (high variance) — exactly the raw material ensembles need.**

### A tree is a sequence of questions

Imagine deciding whether a loan will default. A tree might ask:

1. Is debt-to-income above 40%?
2. If yes, has the borrower missed a payment before?
3. If no, is income below 50,000 USD?

None of this is exotic — it is what a credit officer does with a checklist.

Each internal node asks one yes/no question of the form $x_j\le s$. Read that condition out loud: "is feature number $j$ at most the threshold $s$?" One feature, one number, one comparison. Each answer sends the row left or right. A **leaf** is the group of training rows that gave the same sequence of answers. For classification, the leaf predicts a class proportion; for regression, it predicts an average outcome.

This makes a tree a piecewise-constant model. It does not learn one global equation; it divides feature space into rectangular regions and gives every point in a region the same prediction.

This is also how a tree captures an **interaction** — a feature whose effect depends on another feature's value. Take the rule "high debt is risky, but *only when* the borrower already has a prior delinquency." A linear model cannot say that. It scores each feature on its own: $\text{score} = a\cdot\text{debt} + b\cdot\text{delinquency}$ charges a fixed amount for debt and a fixed amount for delinquency, regardless of the other. To make debt's penalty depend on delinquency, you have to add a new column by hand — the product $\text{debt}\times\text{delinquency}$ — and you have to guess in advance that this is the interaction worth building.

A tree needs no such column. It splits on delinquency first, then asks the debt question *only inside* the branch of borrowers who have a prior delinquency. That question reaches those rows and no others, so debt's effect is already conditional on delinquency. The interaction comes from the nesting of the splits, not from a term someone added by hand.

Look at the rectangles first, not the branches: every leaf is a rectangle, and every rectangle predicts one constant value. That's the whole 'piecewise-constant, axis-aligned, thresholds and interactions for free' story in one picture — logistic regression can't draw this partition, but a depth-3 tree learns it in one greedy pass." />

### What makes one question better than another?

At any node you have hundreds of candidate questions. You need a number that says which one is best, so start from what you actually want. A useful split creates children whose outcomes are more alike than the parent's. **Impurity** is just a numerical score for how mixed a node is.

The simplest such score is **Gini impurity**. Write $p_k$ for the fraction of the node's rows that carry class $k$. Then

$$G = \sum_k p_k(1 - p_k) = 1 - \sum_k p_k^2.$$

There is a clean way to read that sum. Pick a row from the node at random, then guess its label by picking a *second* row at random and copying its class. The term $p_k(1-p_k)$ is the chance the first row is class $k$ while the guess is not, so summing over the classes gives the probability that the two disagree. A pure node never disagrees; an evenly mixed node disagrees as often as possible.

Now do the arithmetic on the two extremes. For a binary node that is 50% positive and 50% negative, $G = 0.5(1-0.5) + 0.5(1-0.5) = 0.5$ — maximally mixed. For a pure node one $p_k$ equals 1 and the rest are 0, so $G = 0$. A split that turns one mixed group into two nearly pure groups has learned something useful. A split that produces two children with the same class proportions as the parent has learned nothing.

A CART tree greedily splits the data with axis-aligned cuts. Write $R$ for the set of rows sitting at the current node and $N$ for how many rows that is; a candidate question sends $N_L$ of them into a left group $R_L$ and the remaining $N_R$ into a right group $R_R$, and $I(\cdot)$ stands for whichever impurity score you have chosen. At each node CART searches over (feature $j$, threshold $s$) to maximize the impurity decrease

$$\Delta I = I(R) - \frac{N_L}{N}I(R_L) - \frac{N_R}{N}I(R_R)$$

Read that left to right: take the parent's messiness, subtract the two children's messiness, and weight each child by the fraction of rows that landed in it. What is left over is how much mess the question removed.

The child impurities are weighted by child size. Without the weights, a split could look excellent by creating one tiny pure leaf while leaving almost everyone in an unchanged mixed node.

**Work one split end to end.** A node holds 10 rows: 6 positive, 4 negative. Its impurity is

$$G_{\text{parent}} = 1 - (0.6^2 + 0.4^2) = 1 - (0.36 + 0.16) = 0.48$$

Candidate split A sends $\lbrace 4^+, 1^-\rbrace$ left and $\lbrace 2^+, 3^-\rbrace$ right:

$$G_L = 1 - (0.8^2 + 0.2^2) = 0.32, \qquad G_R = 1 - (0.4^2 + 0.6^2) = 0.48$$

$$\tfrac{5}{10}(0.32) + \tfrac{5}{10}(0.48) = 0.40, \qquad \Delta G = 0.48 - 0.40 = \mathbf{0.08}$$

Candidate split B sends $\lbrace 5^+, 0^-\rbrace$ left and $\lbrace 1^+, 4^-\rbrace$ right:

$$G_L = 1 - (1^2 + 0^2) = 0, \qquad G_R = 1 - (0.2^2 + 0.8^2) = 0.32$$

$$\tfrac{5}{10}(0) + \tfrac{5}{10}(0.32) = 0.16, \qquad \Delta G = 0.48 - 0.16 = \mathbf{0.32}$$

B wins by 4×, and the reason is visible without the arithmetic: it carves off a *pure* leaf of five positives and leaves a strongly one-sided remainder, while A leaves its right child exactly as mixed as the parent was. Being able to run these two columns of numbers on a whiteboard, and then say *why* B is better in one sentence, is the entire tree-splitting question as interviewers ask it.

Gini is not the only choice of $I(\cdot)$. The other standard classification impurity is **entropy** $H = -\sum_k p_k\log_2 p_k$ (information gain $= \Delta H$), again with $p_k$ the fraction of the node's rows in class $k$ and the sum over the classes present. Both Gini and entropy are concave, so a split never increases impurity, and both reward pure children; Gini is cheaper (no log) and the two rarely disagree on which split to pick. (Misclassification error $1-\max_k p_k$ is concave too but piecewise-linear and insensitive to changes in node probabilities, so it's a poor *growing* criterion — it, or the Gini/entropy used for growing, is what's typically used for cost-complexity *pruning*.)

**Regression impurity** is the within-node variance/SSE; writing $y_i$ for the outcome of row $i$ and $\bar y_R$ for the mean outcome of the rows in region $R$, the variance-reducing split is the one that minimizes $\sum(y_i - \bar y_R)^2$ over the rows of each child, and the leaf prediction is that mean $\bar y_R$ (the median under MAE — the same mean-versus-median contrast drawn in c1.2).

Do not over-interpret the difference between Gini and entropy. Both ask almost the same practical question: “Did the split make the labels more predictable?” What matters is being able to compute one candidate split and explain the weighting, not deciding which criterion universally wins.

So far this is a model that can fit almost anything. Flexibility is only half the story; the other half is how much the fitted tree wobbles when the data wobbles.

**Why a single tree is low-bias/high-variance.** Grown deep, a tree interpolates the training data (bias $\to 0$), but the partition is a *discontinuous* function of the data — perturb a few points and a high split can flip, changing the entire downstream partition. That instability is precisely what makes trees the ideal base learner for **variance reduction by averaging**.

The intuition is structural. If a few rows change which split wins at the root, every later question may be asked of a different subset of data. Two trees trained on nearly identical samples can therefore look entirely different. A deep tree can fit complicated truth (low bias), but we do not know which of many plausible trees a finite noisy sample will produce (high variance).

> **Say it in 30 seconds.** "A deep tree can carve a region around essentially any pattern, so its bias is near zero. But splits are chosen greedily and the partition is a discontinuous function of the data — change a handful of rows and a split near the root flips, which re-routes every question below it. So two samples from the same distribution give you two very different trees. That is high variance, and it is exactly the pathology averaging fixes, which is why trees are the base learner ensembles are built from."

One tree on its own therefore needs its capacity capped, which is what pruning does.

**Pruning.** A fully grown tree overfits, so prune by **cost-complexity**: over subtrees $T$ of the grown tree, minimize $R_\alpha(T) = R(T) + \alpha|T|$, where $R(T)$ is the subtree's error on the training data, $|T|$ its number of leaves, and $\alpha \ge 0$ the price charged per leaf — trading fit against size. As $\alpha$ grows from 0 there's a finite nested sequence of optimal subtrees (sklearn: `ccp_alpha`). The same $\alpha|T|$ regularization reappears inside XGBoost.

That objective says: your score is your error plus a rent of $\alpha$ per leaf you keep. Turn $\alpha$ up and leaves that were not paying for themselves get evicted.

*Why penalize $|T|$ rather than depth?* Because leaves are how many independent constant-value regions the tree carves — that's the true capacity. Two depth-5 trees can have wildly different leaf counts (one balanced 32-leaf full tree; one lopsided 6-leaf skinny tree), so depth alone doesn't cap what the tree can memorize. Leaf count does.

## Part 2 — Bagging & random forests

> **Goal — turn one unstable tree into a low-variance committee, and see that the entire benefit is capped by how *correlated* the trees are.**

### Why averaging helps

Suppose several analysts estimate the same quantity. If their errors point in different directions, averaging cancels much of the noise. If they all make the same mistake, averaging repeats it. Ensembles obey the same rule: averaging helps only to the extent that the trees' errors differ.

Given unlimited data the procedure is obvious: draw many fresh training sets, fit a deep tree on each, average the predictions. The high variance of a single tree would wash out. Nobody gets to run that procedure, because we need many plausible training sets and possess exactly one. The **bootstrap** manufactures the rest by drawing $n$ rows with replacement from the observed $n$ rows. Some rows appear multiple times and some are absent. Fit a deep tree to each resample, then average their predictions. This is **bootstrap aggregating**, shortened to **bagging**.

**Bagging** (Breiman 1996): draw $B$ bootstrap samples (size $n$, with replacement), fit a tree on each, and average (regression) or vote (classification): $\hat f_{\text{bag}}(x) = \frac1B\sum_b \hat f^{*b}(x)$, where $\hat f^{*b}$ is the tree fitted to the $b$-th resample, $b$ runs from 1 to $B$, the hat marks a function estimated from data and the star marks one estimated from a resample rather than from the original sample.

The natural next question is how much this buys you, and whether cranking $B$ up buys more. Write down the variance of the average and the answer falls out.

**The decorrelation identity — the key result.** Fix an input $x$ and let $X_b$ be the prediction tree $b$ makes there — a random quantity, because the resample the tree was grown on is random. If each $X_b$ has variance $\sigma^2$ and every pair of trees has correlation $\rho$, the average of $B$ trees has variance

$$\operatorname{Var}\!\left(\frac1B\sum_b X_b\right) = \rho\sigma^2 + \frac{1-\rho}{B}\sigma^2$$

**Derive it, because you should never have to recall it.** Everything follows from one fact: the variance of a sum is the sum of all variances *plus* all covariances. Pull the $1/B$ out (squaring it), then split the double sum into the $B$ diagonal terms and the $B(B-1)$ off-diagonal ones. Each diagonal term is $\sigma^2$; each off-diagonal term is $\operatorname{Cov}(X_i,X_j)=\rho\sigma^2$, since correlation $\rho$ means covariance $\rho\sigma^2$ when both have variance $\sigma^2$:

$$\operatorname{Var}\!\left(\frac1B\sum_b X_b\right) = \frac{1}{B^2}\Bigl[\underbrace{B\sigma^2}_{\text{diagonal}} + \underbrace{B(B-1)\rho\sigma^2}_{\text{off-diagonal}}\Bigr] = \frac{\sigma^2}{B} + \frac{B-1}{B}\rho\sigma^2$$

That is already the answer; the quoted form is just it rearranged. Add and subtract $\rho\sigma^2/B$: $\frac{B-1}{B}\rho\sigma^2 = \rho\sigma^2 - \frac{\rho\sigma^2}{B}$, so the total is $\rho\sigma^2 + \frac{\sigma^2 - \rho\sigma^2}{B} = \rho\sigma^2 + \frac{1-\rho}{B}\sigma^2$. **QED.** Two lines of covariance bookkeeping, no ensemble theory required.

Read the right-hand side as two separate bills. The first one, $\rho\sigma^2$, has no $B$ in it at all. The second one, $\frac{1-\rho}{B}\sigma^2$, has $B$ in the denominator, so it shrinks every time you add a tree.

**Check the extremes, then put numbers on it.** Set $\rho=0$ and the variance is $\sigma^2/B$, the textbook "averaging $B$ independent things" result, which goes to zero. Set $\rho=1$ and it collapses to $\sigma^2$ — averaging identical models changes nothing, exactly as it should. Now fix $\sigma^2=1$ and compare four ensembles:

| Ensemble | Variance | |
|---|---|---|
| One tree | $1.0$ | the baseline |
| $B=100$, $\rho=0.2$ | $0.2 + \tfrac{0.8}{100} = 0.208$ | already sitting on its floor |
| $B=100$, $\rho=0$ | $\tfrac{1}{100} = 0.01$ | what independence would buy |
| $B=100$, $\rho=0.9$ | $0.9 + \tfrac{0.1}{100} = 0.901$ | 100 trees bought almost nothing |
| $B\to\infty$, $\rho=0.2$ | $0.2$ | the floor itself |

Look at the second row against the last. At $\rho=0.2$, one hundred trees have already captured all but $0.008$ of the available reduction — running ten thousand trees instead would buy essentially nothing. Then look at the fourth row: with highly correlated trees, a hundred-tree ensemble has variance $0.901$ against a single tree's $1.0$. **The ensemble is only as good as the trees' disagreement, and $B$ cannot buy disagreement.**

As $B\to\infty$ the second term vanishes, leaving a **floor of $\rho\sigma^2$**. So adding trees only helps until you hit $\rho\sigma^2$ — and **the correlation $\rho$ caps the whole benefit**. Identical trees ($\rho=1$) give no gain; independent trees ($\rho=0$) give $\sigma^2/B$. *This single identity is the entire motivation for random forests.*

The two terms deserve names. $(1-\rho)\sigma^2/B$ is the independent part of the noise, which averaging removes as $B$ grows. $\rho\sigma^2$ is the shared mistake, which survives forever. More trees shrink the first term; only more diverse trees lower the floor.

Watch where each curve stops dropping, not how fast it drops: every curve is shedding the second term as B grows, and every curve hits ρσ² and flattens. Bagged trees (ρ ≈ 0.9) plateau near 0.9 — most of a single tree's variance survives no matter how many you average. Random forests (ρ ≈ 0.3) plateau much lower — the whole reason RF exists is to lower ρ by hiding features at each split." />

If the floor is the problem, the fix has to be an intervention that makes trees disagree. That intervention is one line of code.

**Random forests** (Breiman 2001) = bagging **+ a random subset of $m \le p$ of the $p$ available features considered at each split**. Forcing each split to choose among different features makes the trees disagree more → **lowers $\rho$** → lowers the $\rho\sigma^2$ floor. The trade: smaller $m$ lowers $\rho$ (good) but weakens each tree (raises its bias) — so there's a sweet spot, classically $m=\sqrt p$ (classification) or $p/3$ (regression). Breiman also proved that the generalization error *converges* as $B\to\infty$. Every tree is a fresh draw from the same randomized recipe, so averaging them is just the law of large numbers — taken over the tree randomness, not over the data. The average settles onto a fixed limit instead of drifting. **Adding more trees does not overfit a random forest**; it only converges.

Why randomly hide features? If one predictor is overwhelmingly strong, ordinary bagged trees will choose it near the top again and again. The trees then inherit nearly the same structure and make correlated mistakes. Feature subsampling occasionally forces a tree to discover a different but useful route. The resulting individual tree may be slightly worse, yet the committee can be better because its members disagree productively. You make each member worse on purpose so the average comes out better. That trade is exactly what the knob $m$ controls.

> **Say it in 30 seconds.** "Bagging reduces variance by averaging trees, but averaging only helps to the extent their errors are uncorrelated — the identity says the variance floor is $\rho\sigma^2$. If one feature dominates, every tree splits on it near the root, the trees end up near-identical, $\rho$ is high, and the floor is high. Random forests hide a random subset of features at each split specifically to lower $\rho$. Each individual tree gets slightly worse, but the ensemble gets better, and $m$ is the knob that trades those off."

Two follow-ups fall directly out of this, and both are common. If a forest has stopped improving at a thousand trees, **adding more cannot help** — the $\frac{1-\rho}{B}\sigma^2$ term is already negligible and you are sitting on the $\rho\sigma^2$ floor, so the only lever left is lowering $\rho$ (a smaller $m$). And if you set $m$ to *all* $p$ features, you have switched off the only thing separating a random forest from plain bagged trees: no decorrelation, high $\rho$, high floor. That is not a hypothetical — it is the library default described in the failure modes below.

Bootstrapping has a side effect worth collecting. Every tree ignored some rows, and those rows are a validation set that cost nothing.

**OOB error and the $1/e$ result.** The probability a given row is missed by one bootstrap draw is $(1-\tfrac1n)^n \to e^{-1} \approx 0.368$, so **each tree leaves out ~37% of rows** (~63% in-bag). Scoring each row using only the trees that didn't see it yields a near-free, cross-validation-quality error estimate — the OOB error.

Where does $(1-\tfrac1n)^n$ come from? One draw misses a specific row with probability $1-\tfrac1n$, and there are $n$ independent draws, so the row survives all of them untouched with that probability raised to the $n$.

The same row is eligible to be drawn $n$ times, so “a bootstrap sample has $n$ rows” does not mean it contains $n$ distinct observations. Roughly 63.2% are distinct; the rest are duplicates. For each training row, the trees that omitted it form a temporary validation ensemble. OOB scoring combines those honest predictions across rows.

> **Stop and think.** You add 5,000 trees to a random forest *and* to a gradient-boosted model. One degrades on the test set; one doesn't. Which, and why? *Hint: RF averages i.i.d.-randomized trees, so by the decorrelation identity / LLN it converges to a floor — more trees never hurt. Boosting fits the loss sequentially, so each added round further reduces bias and eventually fits noise — more rounds DO overfit. That's why RF needs no early stopping and GBDT does.*

One more thing before leaving forests, because it is where the model most often gets misread in production. A fitted forest will happily hand you a ranked list of feature importances, and that list is not what most people think it is.

**Feature importance — a trap (ties to c1.1 / c1.3).** Default **impurity (Gini/MDI) importance is biased toward high-cardinality and continuous features** (more candidate cut-points → more chances to look good by chance — Strobl et al. 2007) and is inflated by overfitting (it's computed on training data). Worse, **correlated features split their importance** (two collinear predictors each get ~half), so low importance ≠ irrelevant — the same redundancy that defeats drop-column leakage detection (c1.1) and inflates VIF (c1.3). Prefer **permutation importance on held-out data** — but note it too is distorted by collinearity, so cluster correlated features and permute jointly.

Make that last failure concrete, because it is the one interviewers press on. Suppose $X_1$ and $X_2$ are near-identical copies of the same underlying signal, and that signal genuinely drives the target. Permute $X_1$ alone: the model simply reads $X_2$ instead, accuracy barely moves, and $X_1$ scores near zero. Permute $X_2$ alone and the same thing happens in reverse. **Both features look unimportant, while the signal they carry is the most important thing in the model.** The rule to state is that low permutation importance means "the model can get by without this *column*," not "this *information* does not matter" — and the two only coincide when nothing else encodes the same thing.

The two measures also fail in *opposite* directions, which makes their disagreement diagnostic. A feature that scores high on impurity importance but near zero on held-out permutation importance is the signature of the cardinality artifact: something like a near-unique ID offered an enormous number of candidate cut-points, so it repeatedly won splits and accumulated impurity credit on the training data, yet it carries no signal that survives to held-out rows, so shuffling it costs nothing.

### Explaining one row rather than the whole model

Both importance measures above are global: each returns one number per feature for the entire fitted model, averaged over a whole population of rows. The strongest sentence either one licenses is "income mattered most across applicants."

An analyst holding a single declined application needs a different sentence, one that names a feature, a direction, and a size, for that one row: income pushed *this* application down by some number of points relative to the average applicant. A permutation chart is silent on this. Shuffling income across 50,000 rows tells you nothing about the one row in front of you, and nothing about whether income helped or hurt that particular applicant.

Set up the local question directly. Fix a fitted model $f$ and one row $x$. Let $\phi_0 = \mathbb{E}[f(X)]$ be the model's average output over the population, with $X$ a random row drawn from that population; $\phi_0$ is the score a featureless prediction would give. The thing to explain is the gap $f(x) - \phi_0$: how far this row's score sits from average, and which features are responsible for how much of that distance.

To talk about a feature's effect on this row, you need to be able to ask what the model would say if a feature were not known. Write $F$ for the set of all $p$ features and $S$ for any subset of them. Define

$$v(S) = \mathbb{E}\bigl[f(X) \mid X_S = x_S\bigr]$$

read as: hold the features in $S$ at this row's actual values, let every other feature vary as it does in the population, and average the model's output. Two endpoints follow immediately. Knowing nothing gives $v(\emptyset) = \phi_0$. Knowing everything gives $v(F) = f(x)$. Every subset in between is a partial state of knowledge about this applicant, and the gap to explain is $v(F) - v(\emptyset)$.

**A worked example.** Take a credit model whose output is a score in points, with population average $\phi_0 = 600$. One applicant scores 540, so the gap to explain is $540 - 600 = -60$ points. Three features are involved: low income $I$, a prior delinquency $D$, and high credit utilization $U$. Evaluating $v$ on all eight subsets gives:

| Features known | Value of v(S) | Change from 600 |
|---|---|---|
| none | 600 | 0 |
| I | 580 | −20 |
| D | 572 | −28 |
| U | 584 | −16 |
| I, D | 556 | −44 |
| I, U | 566 | −34 |
| D, U | 554 | −46 |
| I, D, U | 540 | −60 |

**First attempt: what does each feature do on its own?** Read the three single-feature rows: $-20$, $-28$, $-16$. Add them: $-20 - 28 - 16 = -64$. The true gap is $-60$. The solo effects over-count by 4 points, and there is no honest way to hand an applicant a breakdown whose parts do not sum to the whole.

The over-count has a cause. Low income and a prior delinquency are partly redundant, because both are the model's evidence of financial distress. Once the model already knows about the delinquency, learning that income is low adds $556 - 572 = -16$ points rather than the $-20$ it was worth alone. Counting both at their solo values charges the applicant twice for one underlying story.

**Second attempt: what does each feature do last?** Drop one feature from the full set and see how much the score moves back. For income, $v(\lbrace I,D,U\rbrace) - v(\lbrace D,U\rbrace) = 540 - 554 = -14$. For delinquency, $540 - 566 = -26$. For utilization, $540 - 556 = -16$. Sum: $-14 - 26 - 16 = -56$. Now the parts under-count by 4 points. Same failure, opposite direction, same cause: with the other two features already in place, each feature's remaining marginal effect is smaller than its solo effect, so measuring every feature in that saturated state loses the overlap entirely.

The truth is bracketed. Solo effects give $-64$, last-in effects give $-56$, and the real gap is $-60$, sitting between them. That is the diagnosis: **a feature's contribution is not a fixed number, it depends on which other features are already known**, because features interact and overlap. There is no single "correct" state of knowledge at which to measure a feature, so picking one is arbitrary.

**The fix: stop picking, and average over every order of arrival.** Imagine the three features arriving one at a time, in some order, each one moving the score when it arrives. There are $3! = 6$ possible orders. In each order, every feature has a well-defined marginal contribution: the change in $v$ caused by its own arrival. Compute all of them from the table.

| Order | Income moves | Delinquency moves | Utilization moves |
|---|---|---|---|
| I, D, U | 580−600 = −20 | 556−580 = −24 | 540−556 = −16 |
| I, U, D | 580−600 = −20 | 540−566 = −26 | 566−580 = −14 |
| D, I, U | 556−572 = −16 | 572−600 = −28 | 540−556 = −16 |
| D, U, I | 540−554 = −14 | 572−600 = −28 | 554−572 = −18 |
| U, I, D | 566−584 = −18 | 540−566 = −26 | 584−600 = −16 |
| U, D, I | 540−554 = −14 | 554−584 = −30 | 584−600 = −16 |

Every row sums to $-60$, because in any order the three arrivals walk the score from 600 to 540. Check the first row: $-20 - 24 - 16 = -60$.

Now average each column over the six orders, writing $\phi_I$, $\phi_D$ and $\phi_U$ for the three averages.

$$\phi_I = \tfrac{1}{6}(-20 - 20 - 16 - 14 - 18 - 14) = \tfrac{-102}{6} = -17$$

$$\phi_D = \tfrac{1}{6}(-24 - 26 - 28 - 28 - 26 - 30) = \tfrac{-162}{6} = -27, \qquad \phi_U = \tfrac{1}{6}(-16 - 14 - 16 - 18 - 16 - 16) = \tfrac{-96}{6} = -16$$

Because every individual order sums to $-60$, the average over orders does too: $-17 - 27 - 16 = -60$. Add the baseline back and the model's actual output reappears: $600 - 17 - 27 - 16 = 540$.

This average of a player's marginal contribution over all orders of arrival is the **Shapley value** (Shapley 1953), imported from cooperative game theory, where the "players" are features and the "payout" is the model's prediction. Applied to machine-learning predictions it goes by **SHAP**, short for SHapley Additive exPlanations (Lundberg and Lee 2017). Written for general $p$, with $|S|$ the number of features in subset $S$:

$$\phi_j = \sum_{S \subseteq F \setminus \lbrace j\rbrace} \frac{|S|!\,(p - |S| - 1)!}{p!}\,\bigl[v(S \cup \lbrace j\rbrace) - v(S)\bigr]$$

The bracket is feature $j$'s marginal contribution when the features in $S$ are already known. The fraction in front is the fraction of the $p!$ orders in which exactly the features of $S$ arrive before $j$: there are $|S|!$ ways to order the ones before and $(p-|S|-1)!$ ways to order the ones after. For $p=3$ and $|S|=0$ that fraction is $0!\,2!/3! = 2/6 = 1/3$, matching the two orders out of six in which a feature arrives first.

The property doing the work is the one just verified numerically: the attributions plus the baseline reconstruct the prediction exactly,

$$f(x) = \phi_0 + \sum_{j=1}^{p} \phi_j$$

which is called **efficiency** in the game-theory literature and **local accuracy** in the SHAP literature. This is what makes an explanation auditable. A reviewer can add up the reasons given to an applicant and land on the score the system actually produced, so a reason list cannot quietly omit a factor or invent one. Shapley's theorem is that averaging over orders is the *only* attribution rule satisfying efficiency together with symmetry (two features with identical marginal contributions everywhere get identical attributions), the null-player rule (a feature that never changes $v$ gets exactly zero), and linearity in the value function. Every alternative rule violates one of those.

### What an attribution costs, and what it does not prove

Four things go wrong in practice, and each one is a place where a confident-looking bar chart is doing less than it appears.

**Exact computation is exponential.** The sum above runs over every subset of $F \setminus \lbrace j\rbrace$, so it touches all $2^p$ subsets of the feature set. Three features meant $2^3 = 8$ rows in the table above. Thirty features means $2^{30} = 1{,}073{,}741{,}824$ subsets, per row explained. Nobody computes that, so practice uses approximations. **KernelSHAP** samples coalitions and fits a weighted linear regression to their values, which is model-agnostic but noisy and slow. **TreeSHAP** (Lundberg et al. 2020) is exact rather than sampled, and it is exact only for trees: it exploits the fact that a tree already encodes which feature subsets reach which leaf, and pushes all subsets through the tree structure at once. Its cost is $O(TLD^2)$ for $T$ trees with at most $L$ leaves and depth $D$, against $O(TL2^p)$ for brute force. For a 500-tree model of depth 6, so $L = 2^6 = 64$, TreeSHAP costs on the order of $500 \times 64 \times 6^2 = 500 \times 64 \times 36 = 1{,}152{,}000$ operations. Brute force over 30 features costs about $500 \times 64 \times 1{,}073{,}741{,}824 \approx 3.4 \times 10^{13}$, roughly $3 \times 10^{7}$ times more. Exact per-row attribution is a routine thing to ship for a gradient-boosted model and an intractable thing to ship for an arbitrary model, and the tree structure is the entire reason for the gap.

**Correlated features split credit, and the split can look arbitrary.** The symmetry rule is a guarantee under normal conditions and a nuisance under redundancy. If the credit model were handed income twice as two identical columns, the two copies would have identical marginal contributions in every coalition, so symmetry forces them to receive identical attributions. Income's single $-17$ points would be reported as $-8.5$ and $-8.5$. Neither column now ranks near the top of the applicant's reason list, and the underlying driver has been made to look half as important as it is by an ingestion decision. Real feature sets are full of near-duplicates, so the effect is common and partial. The same redundancy that splits impurity importance and defeats single-column permutation splits Shapley attributions too.

**The meaning of "absent" is a modelling choice, and it changes the answer.** The definition of $v(S)$ above conditions on $X_S = x_S$, which respects how features actually co-vary. The other common choice replaces the unknown features with independent draws from their marginal distribution, ignoring their dependence on $x_S$. The **conditional** version keeps every evaluation on realistic data but leaks credit onto features the model never reads, because a feature correlated with a used one shifts the conditional expectation and picks up nonzero attribution. The **marginal**, or interventional, version guarantees that a feature the model ignores gets exactly zero, at the price of evaluating $f$ on combinations that never occur, such as this applicant's income paired with a utilization drawn from someone else. Those two answers genuinely differ, and neither is wrong (Chen et al. 2020). The tree explainer libraries switch between them depending on whether you hand them a background dataset, so the same model and the same row can produce two different reason lists depending on a function argument. Know which one you invoked before you defend the output.

**An attribution is not a causal claim.** Every quantity above is defined in terms of $f$, the fitted model. It describes what the model does with an input, and it says nothing about what would happen in the world if the input changed. A fraud model that latched onto a proxy correlated with the true driver will produce a large, stable, perfectly faithful attribution to the proxy, because the model really does read that column and really does move when it changes. The explanation is correct about the model and false about the world. This distinction is what separates a debugging tool from a policy tool: SHAP is excellent for finding out that your model learned a proxy, and it is not evidence that changing the proxy would change the outcome.

**LIME, the other common approach.** Instead of averaging over coalitions, **LIME** (Local Interpretable Model-agnostic Explanations; Ribeiro et al. 2016) samples perturbed points near $x$, weights them by how close they are to $x$ under a proximity kernel, and fits a sparse linear model to the original model's outputs on those points. The coefficients of that local surrogate are the explanation. What it buys is speed and total model-agnosticism: it needs only the ability to call $f$, and the output is a short list of readable rules. What it costs is stability. The neighbourhood width is a free parameter with no principled setting, the perturbation sample is random, so re-running LIME on the same row with the same model can change the coefficients and even reorder the top features. The surrogate also carries no efficiency guarantee, so its coefficients do not reconstruct the prediction and a reviewer cannot audit them by addition.

**When this stops being optional.** In US consumer lending, a denied applicant must receive an adverse action notice stating the specific principal reasons for the denial, under the Equal Credit Opportunity Act as implemented by Regulation B. The Consumer Financial Protection Bureau restated in 2022 that using a complex or opaque model does not excuse a vague reason. In the EU, Article 22 of the GDPR restricts decisions based solely on automated processing that produce legal or similarly significant effects, and requires safeguards including the ability to obtain human intervention and contest the outcome. The same requirement shows up wherever a model's output lands on a person and that person can demand a reason: fraud holds on an account, content removals, medical triage. In those settings a global importance chart is not a partial answer to the question being asked. It is an answer to a different question.

## Part 3 — Boosting

> **Goal — drive down *bias* by adding weak trees in sequence, each fitting what the ensemble so far gets wrong — which, made precise, is gradient descent in function space.**

### From a committee to a correction chain

Bagging trains trees independently and averages them. Boosting trains trees sequentially. The first tree makes a rough prediction. The second focuses on what the current ensemble still gets wrong. The third corrects the remaining error, and so on.

Think of writing an estimate in pencil and repeatedly adding small corrections rather than replacing the whole answer. Each shallow tree is intentionally limited: it contributes one modest pattern. The sum of many simple corrections can represent a complicated function. A learning rate controls how aggressively each correction is trusted.

Notice what changed relative to Part 2. Bagged trees are deep and individually low-bias, and averaging attacks their variance. Boosted trees are shallow and individually high-bias, and the sequence attacks that bias. Same base learner, opposite pathology, opposite fix.

The cleanest way to hold the two families apart is as two different questions. **Bagging asks: can I average away the noise in many copies of a strong learner?** **Boosting asks: can I sequentially correct the mistakes of the model I have so far?** Everything else follows from that. Bagging is parallel and boosting is sequential, because bagging's trees never look at each other and boosting's round $m$ cannot start until round $m-1$ is scored. Bagging is robust to label noise and boosting is not, because a mislabeled row is one dissenting vote in an average but a permanent unmet target in a correction chain. And more trees never hurt a forest but eventually overfit a boosted model, for the same reason.

That framing also answers the sharpest version of the question. If your base learners are already *low variance but biased* — shallow stumps, a heavily-constrained model — then averaging them is close to pointless, because there is little variance to cancel and averaging does nothing about bias. **Boosting is the promising direction**, and this is precisely why boosted models are built out of shallow trees while forests are built out of deep ones.

The first algorithm to do this did not talk about gradients at all. It talked about weighting rows.

**AdaBoost** (Freund & Schapire 1997). Start with uniform weights. Each round: fit a classifier $G_m$ to the weighted data, compute its weighted error $\text{err}_m$, give it vote

$$\alpha_m = \ln\frac{1-\text{err}_m}{\text{err}_m}$$

then up-weight the misclassified points and repeat; predict $\text{sign}(\sum_m \alpha_m G_m)$. A classifier at chance ($\text{err}=0.5$) gets weight 0; a perfect one gets $\infty$. Labels here are coded $y\in\{-1,+1\}$ and each $G_m$ outputs $\pm1$, so the product $y\,G_m(x)$ is $+1$ on a row the classifier gets right and $-1$ on one it gets wrong. That coding is what turns the reweighting rule from a heuristic into something exact. Attach the quantity $e^{-yf}$ to the running score $f=\sum_m \alpha_m G_m$. Each round multiplies that quantity by $e^{-y\alpha_m G_m}$, so up-weighting a row every time it is misclassified is nothing but the bookkeeping of $e^{-yf}$. Choose each round's classifier and vote to make $e^{-yf}$ as small as possible, and you recover AdaBoost line for line. That procedure has a name: **forward-stagewise additive modeling under exponential loss** $L(y,f)=e^{-yf}$ (Friedman, Hastie, Tibshirani 2000). It also explains AdaBoost's fragility to label noise — a mislabeled point gets exponentially up-weighted.

That vote is the log-odds of getting the answer right. Say it as a sentence: how often this classifier is right, divided by how often it is wrong, then take a log so the votes add instead of multiply. The two endpoints follow immediately. At $\text{err}=0.5$ the ratio is 1 and the log is 0, so a coin flip is given no say. As $\text{err}$ approaches 0 the ratio blows up and so does the vote.

The label-noise clause is the practical consequence, and it is worth pausing on. A point the ensemble keeps getting wrong is, under exponential loss, a point whose weight grows without bound. If it is genuinely hard, fine. If the label is simply wrong, AdaBoost will spend the rest of its rounds chasing a typo.

Reweighting rows is a trick that works for one specific loss. The generalization drops the trick and goes after the loss directly.

**Gradient boosting** (Friedman 2001) generalizes this to *any* differentiable loss by reframing boosting as **gradient descent in function space**. At round $m$, and for each training row $i=1,\dots,n$, compute the **pseudo-residual** (negative functional gradient), in which $L$ is the chosen loss, $y_i$ is that row's outcome, $f(x_i)$ is the score the ensemble currently assigns it, and the bracket is evaluated at $f_{m-1}$, the ensemble built out of the previous rounds:

$$r_{im} = -\left[\frac{\partial L(y_i, f(x_i))}{\partial f(x_i)}\right]_{f=f_{m-1}}$$

fit a regression tree to the $\{(x_i, r_{im})\}$, and add that tree, call it $h_m$, with a **shrinkage / learning rate** $\nu \in (0,1]$ controlling how much of it is trusted: $f_m = f_{m-1} + \nu\, h_m$. For squared loss the pseudo-residual is just the ordinary residual $y - f$ (so "plain GB" = "fit the residuals"); for log loss it's $y - p$; for MAE it's $\text{sign}(y-f)$. Smaller $\nu$ with more rounds generalizes better (regularization), and **stochastic GB** (Friedman 2002) subsamples rows per round for extra variance reduction.

Read the pseudo-residual out loud before moving on. For row $i$, it asks how the loss would change if you nudged that row's prediction up a little, then flips the sign so the number points downhill. The bracket with $f=f_{m-1}$ underneath means you evaluate that derivative at the ensemble you have built so far, not at some final answer you do not have yet.

**Run two rounds by hand.** Six rows, $x = 1,\dots,6$ and $y = 1,1,1,10,10,10$, squared loss, learning rate $\nu=0.1$. Round 0 is the constant that minimizes squared error, the mean: $f_0 = \bar y = 5.5$. The pseudo-residuals under squared loss are the plain residuals $y - f_0$:

$$r_{i1} = -4.5,\,-4.5,\,-4.5,\,+4.5,\,+4.5,\,+4.5$$

Fit a stump to *those numbers* (not to $y$). The best cut is $x \le 3$, and each leaf predicts the mean residual inside it: $-4.5$ on the left, $+4.5$ on the right. Update $f_1 = f_0 + \nu h_1$:

$$f_1(x\le 3) = 5.5 + 0.1(-4.5) = 5.05, \qquad f_1(x > 3) = 5.5 + 0.1(4.5) = 5.95$$

Both groups moved toward their true values, by a tenth of the way. Round 2 recomputes residuals against $f_1$ — now $-4.05$ and $+4.05$ — fits another stump, and nudges again. Repeat and the two predictions crawl toward 1 and 10. Three things are visible in those numbers and worth saying out loud: the tree is fitted to **residuals, so its leaf values are corrections rather than predictions**; the learning rate means each correction is **deliberately under-applied**; and nothing about this construction ever needed the loss to be squared error.

“Gradient descent in function space” sounds more exotic than it is, and the cleanest way to see it is to put the two updates side by side. Ordinary gradient descent moves a finite parameter vector:

$$\theta_{t+1} = \theta_t - \eta\,\nabla_\theta L$$

Gradient boosting moves the *prediction function itself*:

$$f_{t+1}(x) = f_t(x) + \nu\, h_t(x)$$

The correspondence is exact, term for term. In both cases you evaluate the downhill direction at your current position, scale it by a small step size, and add it on. The only thing that changed is what "position" means: a point in $\mathbb{R}^p$ in the first line, an entire function in the second. The pseudo-residuals $r_{im}$ are the negative gradient evaluated at the $n$ training points, which is all the information you have about the downhill direction. The tree $h_t$ is what turns those $n$ isolated numbers back into a *function* defined everywhere, by grouping rows that share patterns in $X$. That regression step is the one piece with no counterpart in ordinary gradient descent, and it is why the method is called *boosting* rather than just descent.

Turn the loss knob and watch what the correction asks for:

- Under squared loss, a prediction 3 units too low requests a correction of $+3$.
- Under log loss, the correction is $y-p$: a positive example predicted at $0.1$ requests a much larger upward move than one predicted at $0.9$.
- Under MAE, only the direction of the error matters, not its magnitude, which is why MAE is more resistant to outliers.

Gradient boosting uses the slope of the loss. The obvious follow-up is whether the curvature is worth using too, and one library's answer to that made it the tabular default for a decade.

**XGBoost** (Chen & Guestrin 2016) uses a **second-order (Newton)** objective — gradient *and* Hessian — plus explicit regularization $\Omega(f)=\gamma T + \tfrac12\lambda\|w\|^2$, in which $T$ counts the leaves of the tree being added, $w$ collects the values those leaves predict, $\gamma$ is the toll charged per leaf and $\lambda$ the L2 penalty on leaf values. A 2nd-order Taylor expansion (with $g_i, h_i$ the first and second derivatives of the loss at row $i$, both taken with respect to that row's current prediction) makes each leaf a quadratic in its weight, so the **optimal leaf weight** — starred to mark the minimizer — and the **split gain** are closed-form:

$$w_j^\star = -\frac{G_j}{H_j + \lambda}, \qquad \text{Gain} = \tfrac12\!\left[\frac{G_L^2}{H_L+\lambda} + \frac{G_R^2}{H_R+\lambda} - \frac{(G_L+G_R)^2}{H_L+H_R+\lambda}\right] - \gamma$$

where $I_j$ is the set of training rows that land in leaf $j$, and $G_j=\sum_{i\in I_j} g_i$, $H_j=\sum_{i\in I_j} h_i$ are that leaf's total slope and total curvature; the subscripts $L$ and $R$ are the same two sums taken over the left and right children a candidate split would create. The leaf weight reads as slope over curvature, with a $\lambda$ added to the bottom to keep it modest. The gain reads as a score for the left child plus a score for the right child, minus the score of the leaf they replaced, minus a fixed toll $\gamma$ for adding a leaf at all.

#### Deriving the leaf weight, so you never have to memorize it

**Goal — get from "add a tree to the loss" to $w^\star=-G/(H+\lambda)$ in four steps you can redo on a whiteboard.**

**Step 1 — write what round $t$ actually costs.** You are choosing one new tree $f_t$ to bolt onto the predictions you already have:

$$\mathcal{L}^{(t)} = \sum_i l\bigl(y_i,\; \hat y_i^{(t-1)} + f_t(x_i)\bigr) + \Omega(f_t)$$

**Step 2 — Taylor-expand, and notice why second order is the natural stopping point.** That loss is awkward because $f_t$ sits *inside* $l$, which can be any function. Expand $l$ to second order around the current prediction $\hat y_i^{(t-1)}$:

$$l\bigl(y_i, \hat y_i^{(t-1)} + f_t(x_i)\bigr) \;\approx\; \underbrace{l\bigl(y_i,\hat y_i^{(t-1)}\bigr)}_{\text{constant}} + g_i\,f_t(x_i) + \tfrac12 h_i\,f_t(x_i)^2$$

First order alone gives a *linear* function of $f_t$, which has no interior minimum — it just says "go as far as you can," leaving the step size to a heuristic. Adding the quadratic term is the cheapest expansion that has a minimum you can solve for, and it converts an arbitrary loss into a plain quadratic. Drop the constant (it does not depend on the tree you are choosing) and it no longer matters what $l$ was: **every loss now enters only through two numbers per row.**

**Step 3 — group rows by leaf.** A tree assigns the *same* value to every row in a leaf, so write $w_j$ for leaf $j$'s value and sum over leaves instead of rows. That is what turns per-row $g_i,h_i$ into per-leaf $G_j,H_j$, and it folds the L2 penalty $\tfrac12\lambda\sum_j w_j^2$ straight into the quadratic term:

$$\mathcal{L}^{(t)} \approx \sum_{j=1}^{T}\Bigl[G_j w_j + \tfrac12\bigl(H_j+\lambda\bigr)w_j^2\Bigr] + \gamma T$$

Each leaf is now an *independent* one-variable quadratic. That independence is the whole payoff of the regrouping.

**Step 4 — minimize.** For a scalar quadratic $aw+\tfrac12 bw^2$, set the derivative to zero: $a + bw = 0 \Rightarrow w=-a/b$. Here $a=G_j$ and $b=H_j+\lambda$:

$$\frac{\partial}{\partial w_j}\Bigl[G_j w_j + \tfrac12(H_j+\lambda)w_j^2\Bigr] = G_j + (H_j+\lambda)\,w_j = 0 \;\Longrightarrow\; w_j^\star = -\frac{G_j}{H_j+\lambda} \quad \textbf{QED}$$

Substituting $w_j^\star$ back gives that leaf's best achievable contribution, $-\tfrac12 G_j^2/(H_j+\lambda)$. So the whole tree scores $-\tfrac12\sum_j G_j^2/(H_j+\lambda) + \gamma T$, and **the split gain is just that score before minus after**: one leaf with $(G_L{+}G_R, H_L{+}H_R)$ becomes two leaves, and you pay $\gamma$ for the extra leaf. That is the Gain formula above, with nothing else in it.

**Read the four symbols.** $G_j$ is the total slope: it says *which way and how badly* this leaf's rows want the prediction moved, so it sets the direction. The **minus sign** is the same minus that appears in $\theta - \eta\nabla L$ — the gradient points uphill and you move against it. $H_j$ is the total curvature: large curvature means the loss turns sharply, so the quadratic approximation is only trustworthy nearby and the step must be *smaller*; this is exactly Newton's $-g/h$ step, cautious where the loss bends fast. And $\lambda$ only ever enlarges the denominator, so it **shrinks every leaf value toward zero** — L2 regularization applied to the corrections themselves.

**Put numbers on it.** Take log loss, where $g_i = p_i - y_i$ and $h_i = p_i(1-p_i)$. A leaf holds three rows currently predicted at $p=0.5$ (raw score 0) with labels $y = 1, 1, 0$, and set $\lambda = 1$:

$$g = (0.5{-}1),\,(0.5{-}1),\,(0.5{-}0) = -0.5,\,-0.5,\,+0.5 \;\Rightarrow\; G = -0.5$$

$$h = 0.25,\,0.25,\,0.25 \;\Rightarrow\; H = 0.75$$

$$w^\star = -\frac{-0.5}{0.75 + 1} = \frac{0.5}{1.75} \approx 0.286$$

Every part of that is interpretable. The leaf is two-thirds positive, so $G$ came out negative, so $w^\star$ came out **positive** — the leaf pushes the log-odds up, which is what a majority-positive group should do. Drop $\lambda$ to 0 and the same leaf asks for $0.5/0.75\approx 0.667$, more than twice as large: **that gap is exactly what the regularizer bought.** And under squared loss, where $g_i = \hat y_i - y_i$ and $h_i = 1$, the formula becomes $w^\star = \sum_i(y_i-\hat y_i)/(n+\lambda)$ — the **shrunken mean residual**, which is plain gradient boosting reappearing as the special case $h_i=1$.

**This is exactly the c1.2 connection:** for squared loss $h_i=1$, so $w_j^\star$ is the (shrunk) mean residual — recovering plain GB; for **MAE the Hessian is zero**, so $w^\star=-G/\lambda$ is degenerate, which is why naive MAE breaks XGBoost and you reach for `reg:pseudohubererror` or the special-cased `reg:absoluteerror`.

Two later libraries kept this objective and changed how it is computed. **LightGBM** (Ke et al. 2017) speeds it up with leaf-wise (best-first) growth, histogram binning, and gradient-based sampling (GOSS); **CatBoost** (Prokhorenkova et al. 2018) adds ordered boosting (to remove a target-leakage "prediction shift") and native categorical handling.

The Hessian measures curvature: how quickly the gradient itself changes. XGBoost uses that information to scale corrections. A large aggregate Hessian means the local quadratic approximation has strong curvature, so a given gradient implies a smaller, more cautious step. The denominator $H_j+\lambda$ also shows regularization directly: larger $\lambda$ shrinks every leaf value toward zero.

## Part 4 — Stacking

> **Goal — combine *different* model families with a learned meta-model — without leaking.** Train diverse level-0 base learners, then a level-1 meta-learner on their predictions (Wolpert 1992). The non-negotiable detail: the meta-learner must train on **out-of-fold (OOF)** predictions — for each base model, each row's meta-feature comes from a fold that did *not* train on that row. Otherwise an overfit base model (imagine a 1-NN with zero training error) looks perfect in-sample, the meta-learner over-weights it, and the stack collapses at test time. That's pure train/test leakage (c1.1), and OOF prediction is the fix.

Bagging and boosting both combine copies of one model family. Stacking combines different families, and it learns the combination rule instead of fixing it in advance.

The intuition is “learn whom to trust, and when.” A linear model may be reliable in smooth regions, while a tree catches threshold interactions. Their predictions become features for a simple meta-model. The meta-model must see each base learner as it behaves on unseen data. Training predictions answer the wrong question — “how well can this model remember?” — and make the most overfit base learner look like the best expert.

The honest recipe is: split into folds; for each fold, fit every base model on the other folds and predict the held-out fold; stitch those held-out predictions into a complete OOF matrix; train the meta-model on that matrix; finally refit base models on all training data for deployment. Any preprocessing and target encoding must live inside the fold loop too.

## The stats / quant-research lens

> **Goal — the lens a quant interviewer applies: which lever each family pulls, and where calibration and monotonicity bite.**

- **The dichotomy to memorize:** **bagging/RF reduce variance** (average low-bias/high-variance trees; bias ≈ a single tree's), **boosting reduces bias** (sequentially fit the loss; variance can creep up → can overfit). This is the single most-asked ensemble idea.
- **Boosting = functional gradient descent / forward stagewise additive modeling** — the unifying frame; XGBoost is Newton's method in function space (it uses curvature $h_i$).
- **Calibration (c1.2 tie):** trees/RF/GBDT are **not calibrated** out of the box. Both RF and boosting are *sigmoid-distorted* — their probabilities get pushed *toward* 0.5, so both are **under-confident at the extremes** (Niculescu-Mizil & Caruana 2005): RF because averaging bounded tree votes compresses toward the middle, AdaBoost because margin maximization pushes the mapped scores away from 0/1. A *sigmoid* (Platt) calibrator fits both (isotonic is the alternative), via `CalibratedClassifierCV` on held-out data. Contrast modern deep nets, which are *over*-confident (c1.2).
- **Monotonic constraints** (quant favorite): enforce e.g. "default probability increases in leverage" via `monotone_constraints` (XGBoost/LightGBM/CatBoost) or `monotonic_cst` (sklearn HistGB).
- **Why GBDT dominates tabular:** Grinsztajn et al. 2022 — robustness to uninformative features, rotational non-invariance matching tabular structure, and the ability to fit non-smooth targets.

## Worked decision walk-throughs

**Scenario A: a fresh tabular prediction problem, accuracy matters.** Start with **gradient-boosted trees** — `HistGradientBoostingClassifier`, XGBoost, or LightGBM. They're the tabular default; tune learning rate, depth/leaves, and use **early stopping**.

**Scenario B: noisy labels, little time to tune, want robustness.** **Random forest.** Near-zero tuning, robust to label noise (unlike AdaBoost's exp-loss), parallelizes trivially, and more trees never hurt.

**Scenario C: you need trustworthy probabilities (expected-value decisions).** Whatever the model, **calibrate** it — RF/GBDT are not calibrated out of the box; fit Platt/isotonic on a held-out set and check a reliability diagram (c1.2).

**Scenario D: a competition, chasing the last 0.5%.** **Stacking** diverse base models (GBDT + RF + linear + kNN) with a simple meta-learner — using OOF predictions to avoid leakage.

## Production failure modes

Each of these is a place where a library default or a common habit disagrees with the theory above.

1. **`RandomForestRegressor()` isn't a random forest by default.** In modern scikit-learn its `max_features=1.0` means *every* feature is considered at each split — that's **bagged trees** ($\rho$ high, variance floor high), not the textbook RF. Set `max_features="sqrt"` or `1/3` to actually decorrelate.
2. **GBDT with no early stopping.** More boosting rounds reduce bias and then fit noise — train loss keeps dropping while validation loss turns up. Always early-stop on a validation set.
3. **Trusting MDI feature importance.** It's biased toward high-cardinality features and split across correlated ones — use permutation importance on held-out data (with the collinearity caveat).
4. **Shipping uncalibrated tree probabilities.** Downstream EV math is biased; calibrate.
5. **AdaBoost on noisy/mislabeled data.** Exponential loss exponentially up-weights mislabeled points and chases them; prefer RF or gradient boosting with a robust loss.
6. **Naive MAE in XGBoost.** Zero Hessian breaks the Newton leaf step (c1.2); use `reg:pseudohubererror` or `reg:absoluteerror`.

## Interview gotchas

- **"Bagging vs boosting — what does each reduce?"** Bagging/RF → variance; boosting → bias. Be ready to justify with the decorrelation identity and the stagewise-bias-reduction argument.
- **"Why random feature subsampling in a forest?"** To lower the inter-tree correlation $\rho$, which caps the variance reduction ($\rho\sigma^2$ floor).
- **"Do more trees overfit?"** RF: no (converges); GBDT: yes (early-stop). Know *why* (LLN vs sequential bias reduction).
- **"What loss does AdaBoost minimize?"** Exponential loss, forward-stagewise; derive the stagewise coefficient $\beta=\tfrac12\ln\frac{1-\text{err}}{\text{err}}$ (vote $\alpha_m=2\beta=\ln\frac{1-\text{err}}{\text{err}}$).
- **"What does gradient boosting fit at each step?"** The negative gradient (pseudo-residual); for squared loss that's the residual.
- **"Derive XGBoost's leaf weight."** $w^\star=-G/(H+\lambda)$ from the 2nd-order objective; note MAE's zero Hessian breaks it (c1.2).
- **"Why can feature importance mislead?"** Gini cardinality bias + correlated-feature splitting (c1.1/c1.3).
